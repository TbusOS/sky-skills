第 1 级 · 文字

按 ASD-STE100 打八折写:一句一事,写出谁做。

ASD-STE100(简化技术英语)本来是飞机维修手册用的受控英语:读者常常不是母语者,读错了没处问。AI 写的长句、被动句、同一个东西换着叫,正是读错的来源。原标准太严,照搬会写成电报,所以只取八成。中文同样适用。

七条规则

  1. 一句只说一件事三件事就写三句。
  2. 写出谁做「配置会被加载」→「驱动在 probe 时加载配置」。
  3. 同一个东西只用一个名字别一会叫「桥接模块」、一会叫 bridge。
  4. 句子短说明句 ≤ 25 词 / 50 字,操作句 ≤ 20 词 / 30 字。
  5. 动词直接写「对固件进行烧录」→「烧录固件」。
  6. 一步一个动作,条件写在前面「如果重启后没有输出,检查波特率。」
  7. 不确定就直说「应该是」→「我没查到 X,要查就跑 Y」。

开关:说「用 STE 讲」,之后每条回答都这样写;说「停止」关掉。只在本次会话有效。

第 2 级 · 图

讲的是关系,就先给图,再写字。

谁调用谁、哪个仓库同步哪个、启动卡在哪一级 —— 这类问题写成一段字,读者要自己在脑子里画一遍。终端里先画几行 ASCII 图:不超过 80 列,汉字按两列算。图必须带出文字里看不出的判断;只是把文字框起来的图,不如不画。

按键中断进来后调用 gpio_keys_gpio_isr(),它在 wakeup 按键时处理唤醒,然后看 debounce_use_hrtimer:为真就用 hrtimer_start() 起一个高精度定时器,到期时 gpio_keys_debounce_timer() 被调用;否则用 mod_delayed_work() 排一个延时任务,到期时 gpio_keys_gpio_work_func() 被调用;这两个函数都调 gpio_keys_debounce_event(),它再调 gpio_keys_gpio_report_event(),最后由 input_event() 把按键值交给 input 子系统。

每个字都对,但「中断函数里没有上报」这件事,得读到第三个分号才拼得出来。

调用链:从上往下,每层挂出处
行号出自一棵 Linux 6.1.141 内核树的 drivers/input/keyboard/gpio_keys.c,只作示意

  按键中断
      │
      ▼
  gpio_keys_gpio_isr()                      :417   不上报,只排一个延时
      │
      ├─ hrtimer_start()                    :439   用 hrtimer 消抖时
      │    └─ gpio_keys_debounce_timer()    :407   到期后调用
      │
      └─ mod_delayed_work()                 :443   不用 hrtimer 时
           └─ gpio_keys_gpio_work_func()    :399   到期后调用

  gpio_keys_debounce_event()                :390   两条路到期后都调它
      │
      ▼
  gpio_keys_gpio_report_event()             :366
      │
      ▼
  input_event()                             :386   按键值交给 input 子系统
图带出的判断:中断函数里没有上报;两条消抖的路到期后汇到同一个函数。所以按键上报比按下晚一个消抖时间,这是设计如此。

正式出图交给设计 skill 的图例库:anthropic(78 张现成 SVG)· apple · glass · relief(内核 / 硬件类)。设计 skill 不够用时,模型要明说缺什么,不硬套。

第 4 级 · 视频

默认不做。先提一句,你点头才做。

视频做起来最贵,看的人也只能从头看到尾,没法过滤、搜索、跳到某一行。只在三种情况下提:要讲的过程里先后和时机就是要点;看的人要被动看完(转给组里、给新人讲);或者你自己提到视频。

点头之后:两条路

路做法
A 无声录屏先做第 3 级的页面(带动画或分步按钮),再用 record_page.cjs 录成 webm。录完自己打开一遍核对:能播、画面在动。
B 配音 + 字幕走 wechat-video-publisher:edge-tts 配音、逐帧截图、ffmpeg 合成并烧字幕。

V2 抓的是「动画在录之前就播完了」「页面开了减少动态效果」这两种情况 —— 录出来都是一张静止图。录屏用的页面最好就是第 3 级做出来、过了检查的那个,视频里的数也就有出处。

检查

每个脚本都带「故意做坏,必须报」的自测。

全绿的自测不等于查到了:用例只有一种形态时,整条路径可能从来没跑过。所以每个脚本还做了反向验证 —— 把检查故意改坏,对应的用例必须变红。

19条自测

check_ste.py:11 条必须报出问题。另外把它故意改坏 14 处(汉字按一列算、不分句、分号断句……),14 处都让对应用例变红。

13条自测

check_page.py:9 条故意做坏(手改页面、源文件变了、引 CDN、脚本报错……)。有一个问题自测查不出:在仓里跑时 node 能自己找到浏览器,从仓外运行就找不到。这是换到仓外手动跑才发现的,已修。

5条自测

record_page.cjs:静止页、动画录之前就播完的页,都必须报 V2;只有一小块在动的页,必须判成在动。V2 数变化像素的占比:静止页 0%,本页首屏 0.42%,门槛 0.1%。

检查覆盖不到的

  • 出处对,不等于算得对。四项检查证明「数据确实从这个文件经 build.py 算出来」,不证明 build.py 的分类规则对。第一次试用时,按时间戳数值分段分错了几行,四项照样全过;改成按事件切才对。
  • STE 开关没有程序状态。只靠 skill 里的说明;上下文压缩后可能丢,丢了就当关着。
  • V2 拿第一帧当基准。页面加载很慢、第一帧还是白屏时,静止页也会被判成在动。
