# 从一份 AI 问答记录里学到的讲法

材料:一份 102 页的网页导出,是 2026-10-18 / 19 两天和一个 AI 搜索助手的对话。
user 追问了 34 轮(按记录里的日期戳数:10-18 23 轮,10-19 11 轮),话题从自旋锁问到调度器。

这里只记**讲法**,不记它讲的内容。user 原话:「它里面技术原理可能讲解的不对,
我们重点是看讲解的思维方式」「当然它的思维方式也不是最好的表达」。

## 拿来用的

| 讲法 | 记录里的样子 | 落到七层的哪里 |
|---|---|---|
| 结论放第一句 | 很多回答开头就是「结论直接摆在第一句:……」 | §4「每节第一句就是答案」 |
| 从读者的直觉出发 | 先说「你提到的这个直觉,其实距离真相只有一步之遥」,再指出直觉在哪个条件下不成立 | §4「从读者的直觉出发」 |
| 按读者的方案推到坏 | user 提了一个更简单的调度方案,它没有直接否定,而是按这个方案算出一个具体的卡顿时长,再引出现有设计 | ⑤ 演变线的引擎 |
| 一帧一帧演 | 两个任务各跑一段时间,分四幕写账本上的数怎么变,最后算出各自分到的比例 | ③ 主路径「一个具体例子贯穿」 |
| 讲演变带痛点 | 「背景 → 机制 → 痛点 → 进化」:每一代先讲上一代坏在哪,再讲这一代加了什么 | ⑤ 每环四格 |
| 分清两种为什么 | user 自己写的「问题从『为什么需要』变成了『为什么选择』」 | ⑤「为什么需要 / 为什么选这个」 |
| 收尾一张对比表 | 两种实现按五个维度对比 | §4「对比用表」 |

## 不学的

| 问题 | 记录里的样子 | 为什么不学 |
|---|---|---|
| 没有全貌 | 每次只答最新一问。全貌是 user 自己用 34 轮追问拼出来的 | 这正是七层要解决的:先给图,追问才有处挂 |
| 夸读者 | 「你的敏锐和死磕精神太棒了」「堪称神来之笔」「已经超越了绝大多数照本宣科的开发者」 | 不带信息,还让人放松警惕 |
| 夸张修辞 | 「灭顶之灾」「直接送你一个 Panic 让你死个痛快」「自己活腻了」 | 读者分不清事实和修辞 |
| 讲得顺,但有错 | 拿源码核了其中三处说法,三处都和源码对不上;其中一处还贴了一段「核心代码」,源码里没有这段 | 流畅不等于正确。所以本 skill 不收技术事实,事实每次在树上现查 |

核对的具体内容是技术事实,不放在 skill 里,和那份记录放在一起。
