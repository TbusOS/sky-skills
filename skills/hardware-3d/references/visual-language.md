# 画风 —— 这一套页面长什么样

62 / 63 两页共用同一套外壳，只有场景、站点、数据流三处不同。照这个做，新页面一眼就是同一家的。

## 一句话

**中性灰棚拍的写实硬件 + 一层克制的深色玻璃界面。** 3D 里几乎不发光，发光全留给数据流。

## 页面骨架（四块，位置固定）

| 位置 | 是什么 | 要点 |
|---|---|---|
| 左上 | 标题 + 一行副标题 | 渐变字，副标题写清"这页讲什么"，移动端隐藏副标题 |
| 顶部居中 | **章节条**（幕）+ 下面一排**站点圆点** | 幕 3 个左右；站点圆点显示序号，走过的变浅，当前的填蓝 |
| 左下 | **说明卡** | 这页的主角，见下一节 |
| 右上 | 渲染状态 + 光圈滑块 + 移轴开关 | 录视频/截图时整块隐藏 |
| 右下 | ❓ 术语表按钮 | 面板从右侧滑入，英文缩写 + 中文名 + 一句话 |

面板一律 `rgba(18,18,21,.74)` + `backdrop-filter: blur(16px)` + 1px 淡边 + 12px 圆角。
强调色只有一个：`#5aa0eb`。**换配色只动这两处**。

## 说明卡：三问文案模板（最重要）

每站的正文**必须**按这三问写，顺序不能换：

```
是什么      本质定义,不是字面翻译
没有它      去掉这个设计,系统在哪一步失效
为什么这样  取舍。替代方案是什么、为什么没选
            (可选)一行英文术语,灰色小字
```

**反面**：只写"它是什么、它怎么工作" —— 读者只会照抄，遇到变体就废。
**正面**（62 号第 8 站）：

> **是什么** 一个 SM 要一块数据，请求带着地址上交叉开关，地址经哈希决定去 8 片 L2 里的哪一片…
> **没有它** 没有交叉开关，SM 只能访问旁边那片 L2，数据一旦不在就没辙
> **为什么这样** 为什么一次拿 256 位而不是只拿要的 32 位？去一趟显存要几百拍，路费太贵，
> 顺手把相邻数据一起带回来，下次大概率用得上

篇幅不够时**砍机制细节，不砍这三问** —— 机制查代码就有，设计意图查不到。

## 3D 标签

HTML 元素按 3D 锚点投影定位 + SVG 引线 + 锚点上一个发光圆点。
- 一站 3~8 条，多了就乱
- 挤在一起靠 `dy` 拉开（正值放到锚点下方）
- 顶部别顶到章节条，底部别压住说明卡
- `live:'键名'` 接实时文字（第几拍、已等待多少周期、当前 R/G/B 值）

## 时钟控件

有数据流的站，说明卡下面出现一条：`⏸ 暂停 / ⏭ 一拍 / 速度滑块 / 拍号`。
**能一拍一拍看**，这是"看得懂原理"和"看着好看"的分界线。

## 配色纪律

| 用途 | 色 |
|---|---|
| 界面强调 | `#5aa0eb` |
| 数据流 · 命令 | 琥珀 `1.0, 0.60, 0.16` |
| 数据流 · 数据 | 青 `0.22, 0.82, 1.0` |
| 数据流 · 像素 | 洋红 `1.0, 0.32, 0.72` |
| 逻辑块本体 | 低饱和灰蓝，**绝不发光** |

**最多三个强调色。** 几何本体一发光，整页立刻退回"科技感动画"，写实白做。

## 叙事结构

三幕，每幕 3~6 站：

1. **由外向内拆** —— 整机 → 拆开 → 剖开 → 放大 → 再放大
2. **数据走一遍** —— 在第一幕建好的真实结构上叠数据流，按拍走
3. **走到终点** —— 输出、显示、或跟另一条路线对比

第一幕最后一站必须是"钻进去看内部总线地图"，第二幕才有地方可讲。
