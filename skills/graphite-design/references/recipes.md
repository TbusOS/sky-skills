# 十类图的画法要点

每类给出:这类图要讲清的是什么、怎么画、动起来时动什么、对应的图例源码。
源码都在 `templates/src/`,改字、改数据、改颜色比照着画快。

## 角色与道具(`10-cast.mjs`)

- 要讲清:谁在做事。机器人代表「替你干活的程序」,比画电脑图标好认;人代表读者自己。
- 画法:圆脑袋、两点眼睛、几笔头发;衣服只用一支彩铅,让人在场景里好找。
  道具每件一两支彩铅。坐姿用 `legs: 'sit'`,锚点放在座位下方约 76×比例的位置。
- 自己加角色:照 `props.js` 的 `P.robot` 写,坐标用局部 (u, v),由 `M(x, y, s)` 换算——
  不要用 SVG 的 `transform: scale`,那样铅笔线宽和彩铅间距也跟着缩,小角色像换了支细笔。

## 场景(`20-scene.mjs`)

- 要讲清:一个比喻。画面只表达一件事(srt-whiteboard 的规矩:每幕一个核心意思)。
- 大场景优先交给出图模型(见 `image-prompts.md`);代码画的场景胜在能动、能换主题。
- 绘制顺序:场景 → 主角 → 道具 → 最后那个「事件」(灯泡亮起来)。最后一步常用 `S.window(t, null, …)` 让它在某一刻出现。

## 电影画风(`20-scene.mjs` 的 `cinema-*`,以及 `reel.html`)

四个手法,单独用哪个都有电影感,一起用最明显:

1. **上下黑边**:2.33:1 左右的画面放进 16:9,上下各约 9% 黑边。黑边和字幕**不跟着镜头动**。
2. **一个光源**:只有一盏灯 / 一束手电 / 夕阳;其余压暗。代码画时用黄色淡涂画出光锥。
3. **镜头慢推或平移**:整个画面 6–12 秒放大 6–12%(`transform: scale`),以要看的东西为中心;平移就是 `translateX`。
4. **环境在动**:雨、灰尘、闪烁的灯。雨是两层短线,远的短而慢、近的长而快,`repeat: infinite`。

- 分镜先画出来(图例 `cinema-storyboard`):每格写镜头怎么动、几秒。做 HTML 时每格就是时间线上的一段。
- 位图镜头上叠的东西(圈、箭头)要和图放在同一个容器里,镜头推近时一起被推近。

## 框图与架构(`30-diagram.mjs`)

- 要讲清:谁调谁、谁在谁里面。
- `P.node` 画框(默认先垫一层不透明纸色,后面的线不会透出来),`P.link` 连两个框,返回连线的点。
- 颜色按「是什么」分:用户一侧蓝、正在讲的那部分橙、存储绿、基础设施灰。
- 动的:一个请求沿着层走下去、带着结果回来(`P.token`);一直有流量的线用 `.flow` 虚线流动。

## 流程图(`40-flow.mjs`)

- 要讲清:走哪条路、在哪分岔、哪条快。
- 判断用 `P.decision` 菱形(黄);分支上写「有 / 没有」,颜色和分支终点一致。
- 动的:一个小圆点按 `S.track` 走一遍路线。**快慢就是要讲的事**:缓存命中那次走得快,没命中那次绕远路。
- 时间写「示意」。没有量过的数,不要写成量出来的。

## 代码大白话(`50-code.mjs`)

- 要讲清:这几行代码此刻在做什么。
- 左边 `P.code` 深色代码卡(两种主题都深),右边是比喻画面。
- 一条时间表同时驱动三样:代码高亮行(`cursor`)、画面里的动作(`S.track`)、计数(`S.window`)。三者对得上,读者才会信。
- 比喻要标明是比喻(「机器人和箱子是比喻」)。
- **顺序会变的东西**(LRU 链表、排序中的数组,`48-code-deep.mjs` 的 `code-lru`):每个元素单独一组,
  先按模拟记下它每一步在哪,画在最终位置,再把记录换成 `S.track` 的偏移。往前挪的那个先抬起来再走,
  不会从别的节点身上穿过去。
- **会永久消失的东西**(被淘汰的节点、出栈的帧)包进 `S.window(开始, 结束)`:它会带上 `tmp`,
  静态画面里不出现,不会叠在别的东西上。
- **调用栈和调用树一起画**(`code-callstack`):栈就是从根到「当前这次调用」的那条路。树的 x 按叶子顺序排、
  父节点放在孩子中间;一次深度优先遍历生成所有调用和返回的时间,代码高亮、栈、树都从这一张表来。

## 数学与算法(`60-math.mjs`)

- 要讲清:每一步发生了什么。
- **数由代码算,不手写。** 二分查找的步数(`bsearch`)、冒泡排序的交换次数(`events`)、梯度下降每一步的位置(`xs`),
  在 `templates/src/60-math.mjs` 里各跑一遍算法得出;
  说明文字里的数字也引用同一个结果。2026-10-10 第一版说明手写了「四步找到」,实际跑出来是三步。
- 公式每一项一个颜色,和图里对应的部分同色(梯度下降:位置橙、步长紫、斜率蓝)。
- SVG 的 y 轴朝下:「值大的在上面」要写成 `y = 底边 - 值`。第一版梯度下降因此画成了山。
- 两边同步的动画(圆周和正弦波)用同一个开始时间、同一个时长,别各算各的。
- **要和转动同步的点用 `S.track`,关键帧按等时间取。** `S.move` 按路径长度分配关键帧,点在陡的地方跑得快,
  和转动对不上 —— `math-unit-circle` 第一版就是这样,2026-10-10 改掉。
- **套着转的圆**(傅立叶,`58-math-deep.mjs`):嵌套的 `S.animate`,子组只转比父组多出来的那部分
  ((k − k_prev)·360°),`origin` 设在本圆圆心。
- 公式下标用小号、下沉的 `tspan`(`58-math-deep.mjs` 的 `formula()`),不用 ₀₁₂ 这类 Unicode 下标:
  等宽字体子集里不一定有这些字形。
- 实心点(`S.dot`)从 2026-10-10 起按时淡入;`.tok` 这类自己写的实心元素没有描边可画,要包进 `S.window(t, null, …)` 才会按时出现。

## 数据图(`70-chart.mjs`)

- 坐标轴、点、线都是铅笔,但刻度要准:坐标范围从数据算,不要猜。
- 示意数据要写「示意」。
- 标注(「目前最好」「快了 3.1 倍」)里的数也从数据算。

## 标注与叠层(`80-mark.mjs`)

- 叠在截图、照片、出图模型的插画上用:`S.ring` 圈重点、`S.arrow` 箭头、`S.underline` 划线、黄色淡涂当荧光笔、编号圆圈。
- 编号和正文里的 1 2 3 对应,读者不用找。
- 短视频画面(`mark-video-safe`):16:9 字幕离底边 ≥ 8%;9:16 避开右侧一列和底部的平台按钮、文字。

## 越用越懂你(`90-taste.mjs`)

- 要讲清:这个工具怎么从一次次反应里学到一个人的口味。
- **图由学习算法自己画。** 模块顶上 `require('../../assets/taste.js')`,在模拟读者上真跑 `ab` / `pick` / `estimate`,
  曲线上的点、说明里的数都来自这次运行。改了算法,重建一次图就跟着变,不会出现图上画的和代码做的不一致。
- 同一张图换口味(`taste-three`):每位读者用自己的 `Sketch.create({ seed, taste })` 另画一份,种子相同,
  不同的只有口味;线宽、彩铅浓淡这些 CSS 变量包在 `<g style="--g-lw:…">` 里,只管这一组。
- 页面上的说明用 `{{desc:图的 id}}`,直接取图自己算出来的说明文字,不在页面里另写数字。
