# relief-design · 已经踩过的坑

每条都带实测数字或具体机制。没有数字的不往这写。

## §1 中文标题不能靠描边圆角化

想让标题看起来像捏出来的，最直接的念头是给字加同色圆角描边把笔画磨圆。
**中文不行。** 实测六档试样：8px 描边直接把字腔堵死，「设备树DTS是什么？」糊成一团黑块；
拉丁字母没事，因为笔画稀疏。

参考来源那种圆润本来就**不来自字体**，来自 3D 渲染。所以圆润感交给挤出阴影栈和圆角，
字体用 `Noto Sans SC 900` 直接上。

## §2 强调块上不能用白字

| 组合 | 实测对比度 |
|---|---|
| 白字 on 鲜橙渐变 | **2.37:1**（七个皮肤全不合格） |
| 深褐字 on 收窄后的橙渐变 | ≥ 4.5:1 |

橙色暗到能承白字，就不是那个橙了。这是取舍，取的是可读性。
`scripts/check_skin_contrast.py` 守这条线。

## §3 axe 算不了渐变背景

上面那 2.37:1，**axe 一条都没报**。它只看能算出单一背景色的元素。
所以这个 skill 必须跑两道对比度检查，查的不是一回事：

- `check_skin_contrast.py` → 渐变底上的字
- `axe-audit.mjs --theme=<皮肤>` → 真实 DOM 每个元素

## §4 `--theme` 不传就等于没测

七个皮肤不传参数跑 axe，会报出**一模一样的数字**（本仓实测：七次全是 `1 rule, 9 elements`）。
那不是「都过了」，那是把默认皮肤测了七遍。传上参数后数字立刻散开，墨黑报 68 个。

本仓 glass 的浅色主题因为同一个原因漏测 11 天、带着 84 个阻塞元素（known-bugs §6.6）。

## §5 `<button>` 必须显式写 `background`

`<button>` 有浏览器默认底色。浅皮肤下它碰巧接近面料色，**看不出来**；
切到墨黑就是一块浅灰，实测 **1.36:1**。

**坏的方向是「放过」** —— 在开发用的浅皮肤上永远不会暴露。

## §6 `<b>` 不是 SVG 元素

在 `<text>` 里加粗要用 `<tspan font-weight="700">`。用 `<b>` 浏览器可能容忍，
但渲染器规范上会在这里掉出 SVG，后面的内容漏成页面上的散文本。
`visual-audit.mjs` 会报。

## §7 并联的支路不连线

凹槽的意思是「信号从这走到那」。时钟树里三个分频器并联挂在同一个 PLL 上，
用凹槽把它们横着串起来 = **把并联画成了串联**。这是图错了，不是不好看。

## §8 地址图的地址标在区块底边

地址往上增长，所以一个区块的**起始地址在它的底边**。标在顶边，
读者会当成上边界的地址 —— 而且这种错不会有任何提示。

## §9 固定像素宽的部件要包 `.relief-pan`

状态机的节点是按坐标绝对定位的，缩不了。960px 宽 + 页面 padding 在 1024px 视口下
**撑出 1032px，整页横向滚动**，每一段正文跟着歪。包一层 `overflow-x:auto` 就行。

## §10 暗色皮肤的高光不能用白

白边在近黑底上读作**发光灯管**，物体不像鼓起来，像在自己发光。
暗色的高光要用「比底色亮一点的同色」，暗影用「比底色暗一点的同色」。

代价是明暗差被压扁，位移要加大：浅色 9/18，`ink` 11/22，`matte` 12/24。

## §11 半透明标签底会把面料压暗

给属性标签加 `rgba(...,.14)` 的底，实测把面料压暗约 **15 级**。
而前景色是照**纯面料**验的对比度、余量不到 0.5，一压就破。

改成描边标签（`box-shadow: inset 0 0 0 1.4px currentColor`），不动底色。

## §12 术语表不是可选项

`verify.py` 会报「N 个术语在中文正文里没定义」（known-bugs 1.63）。
硬件框图页一次就报了 8 个：取数 · 物理地址 · 一致性 · 突发 · 片上 · 设备树 · 门控 · 分频。

**一张图要是用了读者没有的词，那不是图，是考试。**

## §13 已知会报但不改的警告

| 警告 | 为什么不改 |
|---|---|
| 术语表卡片 `hollow card ... aspect=1.84:1` | 术语卡就是「一个词 + 一句定义」，这是它的固有形状 |
| 内存布局 `asymmetric 3-col grid 132/860/96px` | 地址栏 / 区块 / 大小三列本来就不该等宽，等宽反而读不出主次 |
| `LCP 6176ms` | 本地渲染的指示值，主要是 Google Fonts 往返 |

## §14 别把工作笔记当页面正文

canonical 页是**成品**，不是过程记录。草稿里写「我上一版错在哪」可以，
搬进 canonical 要改成「四档质感，一个配方」—— 读者不关心作者走过什么弯路，
只关心哪个是对的、为什么。

## §15 裸类名（不带 `relief-` 前缀）会坏，但不报错，而且**两道检查都看不见**

写 `class="sn"` 而 CSS 里是 `.relief-stage .relief-sn` —— 规则永远不匹配，
文字回落到继承色。深蓝的继承色压在深蓝渐变块上，实测在渲染图里完全读不出来。

三道检查都放过了它：

| 检查 | 为什么没抓到 |
|---|---|
| `axe-audit` | 背景是渐变，**它算不了渐变背景**，直接跳过这个元素 |
| `check_skin_contrast.py` | 它查的是**变量定义得对不对**，不查页面有没有用对类名 |
| `verify.py` 的「未定义类名」 | `used_classes()` **只收以 skill 前缀开头的 token**，裸类名它根本不采集 |

只有看渲染图才发现。**所以每加一张新页，截图必须人眼过一遍** ——
这不是保险，这是唯一能看到这类问题的通道。

## §16 `inline-flex` 放进 grid 会被拉满整列

`.relief-mux` 是 `display:inline-flex`，按说只有内容那么宽。
但 grid 项默认 `justify-self:stretch`，它会被拉成整列宽，右边拖一条空尾巴。
加 `justify-self:start`。

## §17 新引入一个颜色角色，就要同时加进对比度检查清单

代码面板的关键字一开始借用了 `--orange-d`。那个角色的本意是「强调块渐变的暗端」——
在橙色块**上面**用的，不是在面料上当前景色用的。拿它在面料上写字，实测 **3.42:1**。

**两道检查都没拦住**：`check_skin_contrast.py` 的清单里没有这个角色（它只查列出来的那几对），
axe 倒是报了，但那是在页面写完之后才发现。

所以规矩是：**新加一个前景色角色 → 同一次改动里把它加进 `CHECKS`**。
借用一个现成角色之前先问它原本是在什么底色上用的。

## §18 横向滚动的容器要能用键盘

`overflow-x:auto` 的块（代码面板、描述符链、宽框图）不加 `tabindex="0"`，
键盘用户滚不动它。axe 的 `scrollable-region-focusable` 会报。
加 `tabindex="0" role="region" aria-label="…"` 三件一起。

## §19 端口撞车会伪装成「全部失败」

后台在跑 axe 的时候前台再跑一次，会拿到 `EADDRINUSE`，输出看起来像检查失败。
**先看错误文本是不是 EADDRINUSE，再下结论。**
反过来也一样：那次后台跑出的七个 ✗ 是真的，我一度以为也是端口问题 ——
**两种可能都要分清，不能因为见过一次假的就把真的也当假的。**
