# atelier · SVG 图示工艺

## §1 图放什么

应用界面里的图不是插画,是**读者当下要回答的那个问题的答案**。
问不出问题的图不要画。

## §2 纹理进 CSS,信息进 SVG

booking 页的航线图:点阵底是 CSS `radial-gradient` + `background-size`,
SVG 里**只有**两个机场、一条大圆弧、三个标签。

**为什么**:点阵是纹理不是数据。放进 CSS 之后 SVG 只剩下屏幕阅读器该听到的东西 ——
所以 `aria-label` 是一句话,而不是四百个坐标。同时 SVG 从 400 个 `<circle>` 降到 6 个元素。

## §3 示意图要承认自己是示意图

航线图没有海岸线,figcaption 明写 **"示意图,不是航行图"**。

一张 80% 准确的地图会邀请读者去量它;一张说清自己是什么的图,给出同样的信息
(方向、距离、两个端点)而不撒谎。

## §4 硬性尺寸

- SVG 文字源尺寸 **≥11px**,渲染缩放 ≥0.82(低于 9px 渲染值被闸拦)。
- 内容必须**铺满画布** —— 内容只占宽度 56% 会被 `svg-letterbox` 拦。
  收紧 viewBox 到贴合内容(边距 ≤24px),或把内容摊开。
- 每个 `<svg role="img">` 必须有 `aria-label`,写**结论**不写形状:
  "评分从 2025 一季度的 71 升到 2026 三季度的 92,七个周期都高于团队中位数",
  不是"一条上升的折线"。

## §5 绘制顺序 = 图层顺序

半透明面积填充画在文字之后,会**盖住文字**。

真实踩坑:detail 页的 "median 71" 标签写在面积路径之前,被 30% alpha 的渐变盖成 100% 重叠,
`svg-shape-over-text` 闸抓到。修法是把标签移到所有填充之后绘制。

**规矩**:所有 `<text>` 放在 SVG 的最后。

## §6 颜色

图内颜色走 `data-display.md` §1 的同一套:一条渐变 + 中性轨道 + 参照灰虚线。
`<defs>` 里的 `linearGradient` id 加 `atl-` 前缀避免多图冲突。

图内**不要**用 `currentColor` 取文字色 —— 双主题下会跟着翻,但轨道不会,对比度会崩。
用 token:`fill="var(--atl-ink)"` / `var(--atl-ink-2)` / `var(--atl-ink-3)`。

## §7 界面内图示(长在产品里的技术图)

### 什么属于这里,什么不属于

**不属于**:寄存器位域、SoC 框图、时序波形、协议分层、地址映射。
那些是**文档页**的图,anthropic / apple / primer 各有一整套画法。
atelier 不画文档页 —— 把编辑类图塞进 app 壳里,做出来的东西两边都不像。

**属于**:服务拓扑、流水线状态、权限归属、编排画布、分布地图。
判据一句话:**这张图在真实产品里会不会是一块可以点的面板**。是,就归这一节。

模板:`templates/diagrams/service-topology.html` · `pipeline-status.html`。
注意它们是 **`.html` 片段不是 `.svg`** —— 界面内图示的一半是面板壳和交互接线,
单独一个 `.svg` 文件装不下这一半。

### §7.1 它和编辑类图差在哪

| # | 差别 | 后果 |
|---|---|---|
| 1 | 编辑图是**画完的**,界面图有**状态** | done / running / pending / failed / empty / selected 是同一个形状的六种渲染,不是六张图。少画一种,那种状态发生时界面就是空的 |
| 2 | 它坐在**面板**里 | `.atl-card` + `__head`(标题 + 一句副文 + 一个状态 chip),不是裸 `figure` + `figcaption` |
| 3 | 节点挂**会变的值** | 文字不能焊进 path;标签预算也和编辑图不同 —— `96 ms` 明天可能是 `1.2 s`,位置要留得下 |
| 4 | 必须扛 **1080 侧栏塌缩** | 只在 1440 成立的拓扑是坏的(app-shell §7) |
| 5 | 要**接得上点击** | atelier 的 JS 是交付物的一半,一张点不动的图在这套语言里是半成品 |
| 6 | **选中态就是这一屏的那张近黑锚点卡** | 见下 |

### §7.2 选中怎么做 —— 不写新 JS

`atelier.js` 已经有 `data-tab` / `data-tabpane` / `data-tab-group`。节点直接用它:

```html
<g class="topo-node is-active" data-tab="svc-payroll" data-tab-group="topo"
   role="button" tabindex="0" aria-label="payroll-svc, degraded"> … </g>
…
<div class="atl-card" data-tabpane="svc-payroll" data-tab-group="topo"> … </div>
```

- **`is-active` 写死在 markup 里**。这是 `atelier.js` 的 freeze 契约:终态永远是标记里已经写着的那个,
  所以没有 JS 的读者、截图闸、和点过一轮的人看到的是同一个连贯状态。
- **`role="button"` + `tabindex="0"`** 一个都不能省 —— `<g>` 默认不可聚焦,
  少了它键盘用户根本到不了这张图。
- **外层 `<svg>` 用 `role="group"`,不能用 `role="img"`。**
  `role="img"` 宣称的是"一张原子图像,没有可暴露的子节点";
  里面塞可聚焦的节点就自相矛盾,axe 的 `nested-interactive` 会当 serious 抓
  (本节模板第一版就是这么写的,实测报出来)。
  `group` 会把子节点暴露出去,正是可交互图需要的;
  **整图的那句总结仍然挂在 `aria-label` 上** —— 不想逐个走六个节点的人还是一句话就拿到结论。
- **选中的那个节点就是这一屏唯一的暗卡**(`atelier-material.md` §6)。
  推论很硬:**旁边的详情面板必须是普通卡**。两张暗卡在一屏上会把落点劈成两半,两张都不赢 ——
  这条在本节的模板上真踩过一次。

### §7.3 全 SVG,还是 SVG 画线 + HTML 画节点

**默认全 SVG**:一套坐标系,塌缩时整体缩放,不会在换档处错位。
代价是文字不会 reflow、焦点环要自己写。

**什么时候改用 HTML 节点**(SVG 只画连线):节点文案要换行 / 值特别长 / 需要真正的 tab 顺序与原生焦点环。

**不许混着来** —— 用 CSS 栅格摆 HTML 节点、再用 SVG 坐标画线连它们,
视口档一变两套坐标就对不上,而且只在某几个宽度下错,最难发现。**一张图选一种。**

### §7.4 渐变的两个真坑(都实测过)

1. **水平直线上的渐变会消失。** `<linearGradient>` 默认 `gradientUnits="objectBoundingBox"`,
   而一条纯水平的 path 包围盒**高度为零**,渐变画进零面积的盒子里就退化了 —— 线直接不见。
   本节模板的 `payroll → redis` 那一段第一版就是这么没的。
   **一律写 `gradientUnits="userSpaceOnUse"` 并给出 x1/x2。**
2. **多个形状各自一条斜坡,读成互不相干的几块。** 五个流水线段各自 objectBoundingBox,
   每段都从珊瑚扫到玫红,于是五段看着像五个不相干的条。
   改成 userSpaceOnUse 跨整行,五段落在**同一条斜坡**上,才读作"一条流水线"。

`<defs>` 里的 id 仍按 §6 加 `atl-` 前缀。

### §7.5 状态怎么上色

- **轨道 = `--atl-track`**,它是量纲不是装饰(同 §5 圆头柱那条)。
- **done** = 渐变 + 低不透明度(它是过去) · **running** = 渐变实色 + `data-grow`
  (它是现在,**而且应该是这一屏唯一在动的东西**) · **pending** = **只有轨道**。
  空轨道读作"还没轮到";**整个框都不画**读作"这次运行里没有这一段" —— 两件事,别混。
- **failed = `--atl-danger` 实色,不是红色渐变。** 渐变是这套语言的签名笔触,
  它标的是主路径;拿它标失败,等于说"失败是这屏的主线"。
- **弱化文字用更浅的 token,绝不叠 `opacity`。** 这是四条对比度铁律的第一条
  (`design-review` 的 `cross-skill-rules.md` §N)—— 本节模板第一版在 pending 标签上
  叠了 `opacity: .55`,正撞这条。

### §7.6 尺寸与塌缩

- viewBox 宽按**面板内宽**取,不是按屏宽:`.atl-page--wide` 的主列约 880。
- 源字号 ≥11、渲染缩放 ≥0.82(§4 已有的硬线)。
  **`.atl-dia` 里的实测值**:图列在 880 的 viewBox 下渲染 750-770px,缩放约 **0.87** ——
  所以 eyebrow 惯用的 10px 会落到 **8.7px**,跌破 9px 底线。这一档里最小源字号取 **11.5**。
  (第一版就是 10,`dense-diagram-labels-small` 当场在权限图和编排画布上报出来。)
- **1080 塌缩时详情掉到图下面,不要跟着挤窄。**
  一张被压进半个窄列的拓扑,在文字还能读的时候就已经读不成图了。

### §7.7 别画

| ❌ | 它教错了什么 |
|---|---|
| 把位域图 / 时序图搬进 app 壳 | 那是文档页的图。放进界面里,页面既不是文档也不是应用 |
| 图里只有名字,没有值 | 那是架构图不是控制台。控制台的读者是来看**现在多少**的 |
| 选中只靠一圈描边,详情面板做成暗卡 | 一屏两个重心。选中节点才是眼睛第一个落点 |
| pending 段整个不画 | 读作"不在这次运行里"。要表达"还没到",画空轨道 |
| 用 `opacity` 压弱化文字 | 对比度铁律第一条;axe 会抓,而且这个仓为它付过 1013 个违规 |
| 节点是 `<g>` 但没有 `tabindex` | 键盘用户到不了这张图 —— 而它是可交互的,这就是可达性缺陷不是小事 |
| 一半 HTML 节点一半 SVG 连线 | 两套坐标,只在某几个视口档错位 |
