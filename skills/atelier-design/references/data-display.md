# atelier · 数据展示

## §1 一条渐变,一层中性轨道

所有序列图形只用 `--atl-grad`(珊瑚→玫红)压在 `--atl-track` 上。

**轨道是量纲不是装饰**:没有轨道,31% 的柱子只读作"矮";有轨道它读作"100 里的 31"。

**第二个色只能是这三种身份之一**:
1. **参照几何**(团队中位数、去年基线、SLO 上限)→ 灰色虚线,`--atl-line-strong`
2. **判断**(涨 / 跌 / 警告)→ `--atl-up` / `--atl-down` / `--atl-warn`
3. **分类构成**(饼图切片)→ 玫红 / 珊瑚 / 琥珀 + 中性,**最多三个色 + 轨道**

❌ 彩虹系列色。一张图里 5 个饱和色 = 通用后台模板。

## §2 选图型

| 问题 | 图型 | 上限 |
|---|---|---|
| 每期多少 | 圆头柱 + 轨道 | 12 根 |
| 怎么变的 | 面积 + 折线 + 参照虚线 | 1 条主线 + 1 条参照 |
| 一个整体怎么分 | 环图 + 中心总数 | **4 片** |
| 几个类别谁大 | 横条 `.atl-hbar` | 5 行 |
| 一行里的比例 | `.atl-meter` | — |

环图 4 片是硬上限。超过 4 片弧长不再可比,图就得靠图例才能读 —— 那说明它已经不工作了。

## §3 数字

- 一律 `font-variant-numeric: tabular-nums`。
- 终值写在 markup,`data-count-to` 镜像它。**动画结束后恢复原始文本**,
  所以货币符号、千分位、后缀永远不会被 JS 重建,也就不会漂。
- 涨跌:**颜色是判断,箭头是方向**。延迟下降是好消息 → 绿色下箭头。
  红色留给真正需要人看的那一个。

## §4 图必须说出自己讲不了什么

每张图配一行说明,回答"这张图最容易被读错的地方在哪":

- "6 月 31% 是因为研发的评估周期错过了校准窗口,34 份落到 7 月 —— 6 月和 7 月要合起来看"
- "唯一那次回落正是设计系统迁移上线的季度,当期评语肯定了这项工作但评的是交付结果"
- "2024 年那一跳是职级带变更、不是普调"

这不是可选的礼貌。**一张不解释自己异常值的图,会引出一场错误的会。**

## §5 表格

- 表头 11px / 0.1em / 大写 / `--atl-ink-3`。
- ID 列用 mono。
- 数值列 `.atl-table__num` 右对齐 + 等宽数字。
- 用 `.atl-meter` 替代一整列裸数字 —— 但**旁边仍然要留数字**,进度条读不出精确值。
- 排序:`data-sort` 在表头按钮,单元格 `data-col`;需要按真实值排时给 `data-value`
  (显示 "IDR 28.5M",排序按 `28500000`)。

## §6 环图的 dash 算法

半径 46,周长 ≈ 289。切片 = `stroke-dasharray: <弧长> <周长-弧长>`,
`stroke-dashoffset: -<前面所有弧长之和>`,`transform: rotate(-90deg)` 从 12 点起。

⚠ 这是**手算**的,不是运行时从百分比推的。改数据必须重算 dash —— 这条写在
`canonical/detail.md` 的已知取舍里,不是 bug 但是维护成本。
