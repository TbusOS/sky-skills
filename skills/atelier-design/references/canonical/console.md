# atelier-design · console canonical(界面内图示)

Loka 的平台控制台。生成任何 atelier **带图**的界面前先读这份,HTML 是参考实现。
图本身的画法在 `../diagram-craft.md` §7;这份只讲**让这一页成立的决策**。

## 让这一页成立的 6 个决策

### 1. 进来的判据是"会不会是一块可以点的面板",不是"是不是技术图"
四张图 —— 服务拓扑、流水线状态、权限归属、编排画布 —— 在真实产品里都是面板。
寄存器位域图不是,所以它不在这儿。
**为什么**:atelier 是本仓唯一画**应用**而不是文档的 skill。
把编辑类工程图塞进 app 壳里,做出来的东西既不是文档也不是应用 ——
两种读法都失败,而不是各得一半。

### 2. 选中的节点就是这一屏那张暗卡
详情面板因此是**普通卡**。
**为什么**:`atelier-material.md` §6 规定一屏恰好一张暗卡,而在一张图上,
故事在图里不在边栏 —— 读者该先落到那个降级的服务,再去读它的详情。
第一版两张都做成暗的,落点当场劈成两半,两张都不赢。

### 3. 选中不写一行新 JS
节点是 `<g data-tab>`,详情是 `[data-tabpane]`,`atelier.js` 已经有这套。
**为什么**:复用它,冻结契约是白拿的 —— 选中态写在 markup 里,
所以无 JS 的读者、截图闸、和已经点过两下的人看到的是同一个连贯状态。
自己写一个选择控制器,这份保证要重新挣一遍。

### 4. 可交互的图用 `role="group"`,不是 `role="img"`
**为什么**:`role="img"` 宣称"一张原子图像,没有可暴露的子节点",
里面放可聚焦的节点就自相矛盾 —— axe 的 `nested-interactive` 按 serious 抓,
第一版实测报出来了。`group` 会把子节点暴露给键盘用户,而整图那句总结仍挂在 `aria-label` 上。
**静态的那张流水线保留 `role="img"`**,因为它里面没有可聚焦的东西。

### 5. 状态用 meter 解剖,不用整块填充
名字和数值在卡上,细的 track + fill 条在下面。
**为什么**:标签一旦骑在饱和填充的边缘,**没有一种颜色成立**;
而 axe 在渐变底上返回 incomplete,**没有任何闸会告诉你这件事**。
把值移进细条,顺带让轨道承担量纲(material §5),也去掉了一条满宽饱和色带 ——
那在这个仓的别处是明令的坏味道。

### 6. 渐变一律 `userSpaceOnUse`
**为什么**:两件事。一条纯水平的连线包围盒**高度为零**,
`objectBoundingBox` 渐变画进零面积的盒子就退化 —— 线直接消失(第一版真的丢了一段)。
而且跨整图的一条斜坡让所有段落在同一条渐变上,五个流水线段才读作"一条流水线"
而不是五个不相干的条。

## 三个抄的时候容易错的地方

- **渐变的 paint 必须是 inline `style`,不能是 presentation attribute。**
  `stroke="url(#…)"` 输给任何一条 CSS 规则,而 `.atl-dia-link path` 正好直接命中子元素 ——
  第一版所有描线因此全是灰的。CSS 侧也配了 `:not(.atl-dia-link--hot)` 让继承值过得来。
- **组件 CSS 在 `atelier.css` Section R,不在页面里。** 四个模板共用一套样式;
  复制进四个页面,第一次只改了三个的编辑就让它们分家了。
- **一屏放四张图是参考页的特权。** 真实产品屏会放**一张**,外加一圈普通面板。

## 交互

| 动作 | 结果 |
|---|---|
| 点拓扑 / 权限 / 编排里的节点 | 右侧详情换成该节点;选中态(暗卡)跟着走 |
| 键盘 Tab | 每个可选节点都在 tab 序里(`role="button"` + `tabindex="0"`) |
| 主题切换 | 暗卡翻成奶油;渐变与轨道走 token,两个主题各自成立 |
| ≤1080 | 详情**掉到图下面**,不跟着挤窄 |
