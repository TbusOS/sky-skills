# atelier · 材质配方

这个 skill 的"物理学"。改任何一条之前先读完 —— 三个数字之间是绑死的。

## §1 壁纸:四个暖色停,不能是纯色

```css
background:
  radial-gradient(58% 52% at  6%   2%, var(--atl-wall-1) 0%, transparent 64%),  /* 深桃 S42 V91 */
  radial-gradient(54% 60% at 98%  22%, var(--atl-wall-2) 0%, transparent 62%),  /* 玫粉 S31 V89 */
  radial-gradient(60% 46% at 46% 104%, var(--atl-wall-3) 0%, transparent 60%),  /* 奶油亮区 */
  radial-gradient(44% 44% at 106% 96%, var(--atl-wall-4) 0%, transparent 66%),  /* 陶土暗端 V79 */
  var(--atl-wall-base);
```

**玻璃感 = 壁纸饱和度 × 明暗跨度 × 壳透明度**(2026-08-14 对参考板采样后重校)。
第一版壁纸 S≤19 / V96+、跨度 1 个点,玻璃后面没有东西可磨,壳读作米白纸。
参考板实测 S27-40、**V54→V93 跨 40 个点**,透过玻璃采到的仍是 `#E3C7B1` 浓桃。
重校后本 skill 玻璃后采样 `#F9D9C1`(v2 是 `#FFE2CB`,红通道已削波,见 §2)—— 进入"透出暖桃"域。
第四停(陶土)是明暗跨度的暗端,中心压在画布外右下角:给磨砂供暗色,
又不把暗底垫到正文底下。

**公式里的"饱和度"有上限,不是越大越透。** v2 想靠 `saturate(180%)` 把颜色压出来,
结果把红通道推到削波 —— 实测玻璃区 **100% 的像素红通道钉在 255**,梯度无处可放,
明暗跨度塌成 1.6 个点。饱和度只在**通道还有余量**时才乘进玻璃感里;一削波,
这一项就从乘数变成了除数。详见 §2「saturate 是必需项,但它是增益级」。

**为什么不能是纯色**:玻璃的可见性来自它折射的东西。纯色底上,`backdrop-filter: blur()`
在数学上仍在跑,视觉上什么都不发生 —— 你付了 GPU 的钱,拿到的是一张半透明白板。
四个停位保证屏幕上任何一处玻璃后面都有可折射的颜色梯度,且含一个暗端。

`.atl-wall` 用 `position: fixed`。**窗口浮着,纸不动** —— 壁纸跟着滚会把"应用浮在桌面上"
读成"一张长图",整个空间比喻塌掉。

一道对角高光 `.atl-wall::after`,**只能有一道**。两道就成了廉价的"光泽"贴图。

**强度:亮色 0.34,暗色 0.16。两个数不成比例,这是量出来的,不是漏改的。**

亮色从 0.55 降到 0.34,方向是对的 —— 高光是白,白洗过 backdrop,壳磨的东西在磨之前
就被提亮了。但**幅度必须说实话:这个参数能动的量很小。** 同一个视口、只改这一个 opacity 的
逐像素实测(dashboard / signin,1440×1000):

| | dashboard | signin |
|---|---|---|
| 单通道最大变化 | 6 / 255 | 6 / 255 |
| 变化超过 3/255 的像素 | 3.4% | 5.4% |
| 玻璃采样点 | 一个字节都不动 | 蓝通道 −4(略暖) |

原因算得出来:高光峰值是 `rgba(255,255,255,.30)`,0.55 → 0.34 等于有效白从 16.5% 掉到
10.2%,压在 `#E9C3A8` 上蓝通道最多也就动 5-6 个数。**"奶白"的主因是削波(§2),
不是这道高光**;把高光当第二个主因去追,会追不到东西。

暗色**不同比例下调,保持 0.16**:实测把它从 0.16 改到 0.10 甚至 0,
玻璃采样点(侧栏上/下、右侧壳留白)的 RGB **一个字节都不动**,变的只有裸壁纸上
被高光带扫过的那一条,明度差 ~2 个点 —— 1× 截图上两张分不出来。
深底上 0.16 × 30% 白本来就没有能力提亮 backdrop,它唯一的作用是给那片深棕留一个可见的
光向;跟着砍掉等于删掉光向,换不到任何透明度。

**规矩只管数量(一道),强度按主题各自量。**

## §2 三层玻璃

| 层 | token | alpha | blur | 职责 |
|---|---|---|---|---|
| 外壳 `.atl-app` | `--atl-shell-bg` | 0.32 | 42px + `saturate(1.45)` | 整个应用窗口。唯一一块。1px 渐变描边 |
| 侧栏 `.atl-rail` | `--atl-rail-bg` | 0.20 | 继承 | 自己再加一层薄纱,所以合成后比壳更雾(见下) |
| 数据卡 `.atl-card` | `--atl-card-bg` | 0.80 | 无 | 承载数字 |
| 实心卡 `--solid` | `--atl-card-2-bg` | 0.94 | 无 | 表格、展开态 |

**只有外壳做 blur。** 卡片再套一层 `backdrop-filter` 会触发嵌套的滤镜链,
每帧重跑两次,而视觉上分辨不出 —— 卡片已经在 0.80 不透明度,后面没剩多少可模糊的。

**侧栏的 alpha 是叠加的,不是替代的。** `.atl-rail` 是 `.atl-app` 的子元素,它的背景画在
壳的薄纱**之上**,所以侧栏实际的白纱是 `0.32 + 0.20 × 0.68 = 0.456`。这条以前写成
"侧栏比壳更透",是错的 —— 侧栏永远是页面上最雾的一块玻璃。这也正是它该有的样子:
导航是家具,退到后面去。想让侧栏真的比壳更透,得把纱移到 `.atl-main` 上,那是另一套结构。

### saturate 是必需项,但它是增益级

```css
backdrop-filter: blur(42px) saturate(1.45);   /* 暗色主题 1.22 */
```

**纯 blur 会把壁纸平均成灰白** —— 这是"奶白感"的第一个来源,所以 saturate 不是装饰。
但它是**增益**,推过头会削波:v2 用 `saturate(180%)` 配 0.42 的近白纱,渲染实测
**玻璃区域 100% 的像素红通道钉在 255**。通道一削波就再也承载不了梯度,于是透过玻璃的
明暗跨度塌到 **1.6 个点** —— 一整片死平的奶油色,这就是"不够透亮"的样子。
1.45 是这张壁纸上最后一档还留有余量的值。

| 指标(dashboard 范本页实测) | v2 | v3 |
|---|---|---|
| 玻璃区域红通道削波像素 | 100%(3/4 区域) | 0% |
| 玻璃平均饱和度 | 24.4% | 26.1% |
| **透过玻璃的明暗跨度** | 1.6 点 | 4.8 点 |

**更低的 saturate 换来更多可见的颜色。** 反直觉,但削波比增益重要。

### 边缘光:一道渐变描边,不是一圈白线

真玻璃的边不是均匀的白:光进来的那一侧(左上)亮,板厚显出来的那一侧(右下)是暖暗。
`--atl-shell-edge` 是一道 146° 的渐变,`rgba(255,255,255,.55)` → `rgba(120,80,60,.12)`,
用 1px 的 mask 环画(`padding:1px` + `mask-composite: exclude`)。

**为什么不用 `border-image`**:它无视 `border-radius`,而这个壳是 28px 圆角。
mask 环包在 `@supports ((mask-composite: exclude) or (-webkit-mask-composite: xor))` 里 ——
没有 mask 的引擎里那个伪元素会糊成一整块盖住整个应用,所以降级回平的 `--atl-shell-border`。

投影是**两层**,因为玻璃有厚度:`--atl-shell-contact` 近距离深色接触影(把板坐在纸上)+
`--atl-shell-shadow` 大范围柔和环境影(把板托起来)。只有环境影时,壳像贴在壁纸上的一张贴纸。

### 砂:3% 的分形噪点

`--atl-noise` 是一张 160×160 的 `feTurbulence` 平铺(data URI,rect opacity `0.028`),
作为**背景层**叠在 `.atl-app` 和 `.atl-rail` 上 —— 磨砂玻璃的"砂"。

用背景层而不是伪元素,是因为祖先的背景永远画在后代之下:噪点因此**不可能**爬到数据卡上。
(伪元素做法要么被 `overflow:hidden` 裁掉,要么盖在数字上,两个都不能接受。)
`backdrop-filter` 不可用时的降级会连带丢掉噪点,这是对的 —— 那时候壳已经是不透明面板了。

## §3 玻璃是外壳,不透明度是数据(核心规则)

> 一个表面越承载数字,就越往不透明走。

外壳 0.32 是因为它是家具:边框、圆角、投影,读者不看它。
表格卡 0.94 是因为读者要在里面比对第三行和第六行的数字。
半透明的数字压在会动的渐变上,读者会不自觉读两遍 —— 这个代价没人愿意为"更好看的玻璃"付。

**反面判据**:如果你的 KPI 数字后面能看见壁纸的颜色变化,alpha 开太大了。

## §4 渐变圆球(签名笔触)

```css
.atl-orb {
  width: 46px; height: 46px; border-radius: 50%;
  background: var(--atl-grad);        /* 珊瑚 → 玫红,158° */
  color: #FFF;                        /* 只放图形,不放文字 */
  box-shadow: 0 8px 18px -8px rgba(221, 79, 146, 0.62);
}
```

**为什么是实心渐变球而不是线性图标 + 细圆环**:这是整套语言里最认脸的一个物体。
线性图标配 1px 圆环是**通用后台模板的标志** —— 它出现在每一个 Bootstrap / Tailwind
admin kit 里。原作者的底子是渐变图标集与 3D 插画,圆球是他的语法,不是装饰。
丢掉这一笔,剩下的暖玻璃只是"另一个 admin 模板"。

**次级变体 `--soft`**:16% 的淡渐变底 + 强调色图形。当一屏里每行都上满渐变,
屏幕会变成彩纸屑。规矩:**主行用实心,列表行用 soft**。

`--lg` 58px 用在记录页头像位;`--sm` 34px 用在紧凑列表。三档,没有第四档。

## §5 圆头柱 + 灰轨道

```
.atl-bars__stack   ← 轨道:全高,--atl-track,圆角 pill
.atl-bars__fill    ← 填充:从底部起,--atl-grad,同样圆角 pill
```

**轨道不是装饰,是量纲。** 没有轨道,31% 的柱子只读作"矮";有了轨道,它读作
"100 里的 31"。这是这个组件存在的全部理由。

两端都要全圆头。只圆上端是 2019 年的 Material 语言,不是这一套。

## §6 那一张暗卡

`.atl-card--ink` = `#211C1A`(不是纯黑 —— 纯黑在暖色页面上像个洞)。

**每屏恰好一张。** 亮底页面上,暗卡是眼睛第一个落点;两张就分裂了落点,两张都不赢。
放什么进去有讲究:**放需要动作的东西**(待录入的调薪、今天的面试队列),
不放已知的汇总。最高对比度的位置花在读者已经看得见的东西上,是浪费。

暗色主题下它翻成奶油 `#F7EFE9`。这一笔是"**一张卡打断明暗节奏**",不是"一张卡是黑的"。

不是卡片的暗区域(分栏面板、通栏)用 `.atl-inksurface`,它带同一套颜色契约。
手写 `background: var(--atl-ink-card-bg)` 而不带这个类,`.atl-muted` 会继续解析成
**亮色主题的**灰,压在深色面板上几乎不可见 —— 这个 bug 在本 skill 的 signin canonical
上骗过了渲染对比度闸,是看截图才发现的。

## §7 降级

```css
@supports not (backdrop-filter: blur(1px)) {
  .atl-app { background: var(--atl-card-2-bg); }   /* 退成不透明,不是退成透明 */
}
```

**不可读的文字比没有模糊糟糕得多。** 不支持 `backdrop-filter` 的环境里,
0.32 alpha 的面板 = 文字直接压在渐变上。降级方向永远是"变不透明"。

## §8 性能

`backdrop-filter` 盖住整窗、后面是三停渐变 —— 这是页面上最贵的一件事。
本 skill 的三条纪律:

1. **只有外壳 blur**(§2)。
2. **不要动画 `clip-path` / `border-radius` / 尺寸**盖在玻璃上 —— 会强制滤镜链每帧重跑。
   `transform` 和 `opacity` 安全。
3. 生产构建滚动时把 `--atl-blur` 降到 20px。canonical 页不做这件事,因为它要确定性截图。
