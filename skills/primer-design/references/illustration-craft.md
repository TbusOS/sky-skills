# primer · 厚描边插画工艺

厚描边插画是 primer 和其余 8 套最不一样的地方(spec §3.3-5),也是这套 skill 唯一
**能靠算术保证质量**的部分。§3 的换算是画任何一张图之前必须先做的一步。

线宽、圆头、圆角接头都由 `assets/primer.css` Section J 给两个插画容器一起设好了 ——
`.primer-figure svg` **和** `.primer-analogy-fig svg`。所以画的时候只写 `<path d="…">`,
线的性格是免费的。要自己写的只有三件:viewBox 多大、哪里平涂、哪里加细节。

## §1 画什么

**画真东西。** 有齿的齿轮、有抽屉和把手的柜子、有页脚和书脊的书、有螺口和玻璃泡的灯泡、
有插头的线。零基础读者认得实物;认不得的是抽象图形。

- **每张图一个主体,主体是紫的。** `--primer-violet` 平涂在这一节真正要讲的那个东西上,
  周边的东西留白或用墨线。读者扫一眼就知道该看哪。
- **一张图只教一件事。** 教两件事的图会同时长出两组标签,然后两组都变小
  (`dos-and-donts.md` §7 第 6 条)。
- **答不上问题的图不画。** 先写出"这一节回答的问题"(`explain-method.md` §6),
  图是那个问题的答案。答不上就说明这一节还没想清,不是缺一张图。

❌ 火柴人、笑脸圆圈、扁平图标 + 一个对钩。这三样是 slop 的公开签名。

## §2 线

| 项 | 值 | 谁给的 |
|---|---|---|
| 主轮廓 | `--primer-stroke` **3.4** | CSS Section J,设在 `<svg>` 上,子元素继承 |
| 内部细节(齿、缝、刻度、纹理) | `--primer-stroke-hair` **1.8** | 加 `class="primer-hair"` |
| 线端 / 接头 | `round` / `round` | 同上,继承 |
| 描边色 | `--primer-ink` `#243244` | 同上。**别写 `stroke="#000"`** —— 纯黑是禁用色(`dos-and-donts.md` §2) |

**改线宽的口子**(知道哪个赢很重要):

- **单个形状** → 直接写 `<path stroke-width="2.6" …>`。表现属性在**它自己的元素上**,
  赢过从 `<svg>` 继承来的值。
- **整张图加粗 → 只能改 CSS,而且必须成对改。**`<g stroke-width="4.4">` 这种包一层的写法
  **只抬得起主轮廓**:`primer.css:388-389` 的 `.primer-figure svg .primer-hair`
  (以及比喻卡那条孪生规则)是**直接命中细节路径自己**的 CSS 规则,它赢过从 `<g>` 继承来的值,
  所以 hair 仍然是 1.8 —— 主线 4.4 / 细节 1.8 = 比 0.41,而 §3 要求的比是 0.53。
  **没有任何机械检查会报这件事**,它只是细节层次看起来塌了一层。正确写法(页内 `<style>`,
  无前缀 class 挂在 `.primer-figure` 上,特异度天然高过 CSS Section J,不依赖代码顺序):

  ```css
  .primer-figure.fig-heavy svg              { stroke-width: 4.4px; }
  .primer-figure.fig-heavy svg .primer-hair { stroke-width: 2.3px; }  /* 4.4 × 0.53 */
  ```

  §3 手机那段用的是同一个手法 —— **主线和细节线永远一起改**。
- ⚠ 在 `<svg>` 自己身上写 `stroke-width="4.4"` **没用** —— CSS 规则命中的就是这个元素,
  表现属性打不过它。真要在 svg 上单点改,写 `style="stroke-width:4.4px"`(内联样式);
  但那同样抬不起 hair,所以它只适合本来就没有细节线的小图。

## §3 viewBox 尺寸律(先算,再画)

**3.4 是 SVG 用户单位,不是渲染像素。** viewBox 越宽,同一根线渲染出来越细:

```
渲染描边 = 3.4 × (渲染宽度 / viewBox 宽度)
```

绘本下限是 **3px**。低于它,画面从"绘本"退化成"图标集" —— 而这件事**没有任何机械检查会报**,
它只是看起来轻。所以反解出上限:

```
viewBox 宽度 ≤ (3.4 / 3) × 渲染宽度 ≈ 1.13 × 渲染宽度
```

### 实测过的位置(渲染宽度按 CSS 算出来的实值)

| 图在哪 | 1440 视口渲染宽 | 1024 视口渲染宽 | viewBox 上限 | **工作值** |
|---|---|---|---|---|
| 比喻卡图栏(桌面 `172px` 固定栏) | 172 | 172 | 194 | **≤190** |
| hero 右栏(`.primer-hero-inner` 1fr / 1.05fr,gap 56) | 492 | 463 | 524 | **≤500** |
| 节内全宽图(`.primer-container` 1080,内容宽 1016) | 1016 | 960 | 1088 | **≤1000**(常用 900) |
| 节内全宽图(`--wide` 1280) | 1216 | 960 | 1088 | **≤1000** |

**上限按两个视口里更窄的那个取** —— 1024 是 visual-audit 的第二视口,不是可选项。
hero 图的 540 在 1440 下是 3.10px,到 1024 就掉到 2.92px,所以工作值写 500(1024 下 3.15px)。

### 一个走完的例子:比喻卡的插画

比喻卡在桌面是 `grid-template-columns: 172px minmax(0,1fr)`,图栏固定 172px,
`svg { width: 100% }` ⇒ 渲染宽度 **172px**。

- ❌ 顺手写 `viewBox="0 0 240 200"`:渲染描边 = 3.4 × 172 / 240 = **2.44px**。
  掉出 3px 下限。症状不是报错,是"这张图看着比别的图轻"。
- ✅ 写 `viewBox="0 0 180 150"`:渲染描边 = 3.4 × 172 / 180 = **3.25px**。
- 上限验算:172 × 1.13 = 194 ⇒ 190 是安全的整数;190 给到 3.08px,刚过线,别再往上。

比喻卡在 ≤768px 时变成单栏,`.primer-analogy-fig { max-width: 220px }` ⇒ 渲染宽度变大到 220,
描边跟着变粗(180 的 viewBox 给到 4.16px)。**手机上比喻卡的图只会更粗,不用管。**

### 窄视口的全宽图:挂 `primer-fig-wide`,别自己写描边

375 视口下 `.primer-container` 的内容宽是 375 − 20×2 = **335px**。一张 900 宽 viewBox 的
节内全宽图在这里渲染描边只有 3.4 × 335 / 900 = **1.27px** —— 图还在,绘本感没了。
visual-audit 的两个视口(1440 / 1024)都看不到这一格,靠人眼看截图。

修法:给全宽图挂 `class="primer-figure primer-fig-wide"`。这个 class **由
`assets/primer.css` Section L 统一提供**,页面里不要再写任何 stroke 规则 ——
它是前缀 class,verify.py 会校验;每个页型都有全宽图,单一来源才不会漂移。

它做的事是一段**三级阶梯**(单一断点会顾此失彼:只在 ≤768 一档加到 9,768 视口上
9 × 728/900 ≈ **7.28px**,是设计线宽的两倍多;只收窄到 ≤480 一档,481–768 的自然线宽
又掉回 1.67–2.75px)。渲染描边 = 值 × 内容宽/900,内容宽 = 视口 − 两侧栏距:

| 视口 | 生效值(主线/细节) | 渲染主线 |
|---|---|---|
| >900px | 3.4 / 1.8(自然值) | 3.03–4.08px |
| 661–900px | 4.4 / 2.3 | 3.04–4.09px |
| 481–660px | 6.4 / 3.4 | 3.14–4.41px |
| ≤480px | 9 / 4.8 | ≤4.4px(375 时 9 × 335/900 = **3.35px**) |

hero 图挂 `primer-fig-hero`(同样来自 primer.css:桌面上它还负责去掉图的块级边距,
让图在 hero 网格里垂直居中)。它的 viewBox ≤500,只有 ≤480px 才跌破 3px 下限
(481–768 的单栏渲染宽 441–728px,自然 3.4 单位已落在 3.0–4.95px),所以只有一级:
≤480px 时 5 / 2.65(375 时 5 × 335/500 = **3.35px**)。

**加粗主线就要同比例加粗 `primer-hair`**(§2 那条同理),否则细节层次在窄视口直接消失
(桌面两者的比是 1.8 / 3.4 ≈ 0.53)—— Section L 的每一级都成对给。两条选择器都带
`.primer-figure`,特异度一定高过 CSS Section J,不依赖规则顺序。

## §4 平涂与 `fill`

**厚描边 + 平涂色块**才是绘本语言;只有轮廓是图标集,只有色块是贴纸。

- **空心形状必须显式写 `fill="none"`。** SVG 的默认 fill 是**黑色**,不是透明。忘了写,
  一个本该是空心圆的形状会渲染成一个黑饼 —— 而且**机械检查不报**(`dos-and-donts.md` §7 第 2 条)。
- 实色平涂:直接写调色板里的 hex(`#7a5cd6` / `#ffd23f` / `#3aa66b` / `#fdfaf3` / `#ffffff`)。
  `fill="var(--primer-violet)"` 这种写法在各浏览器里不稳,不要用;要走 token 就在页内
  `<style>` 定一个无前缀 class(`.fig-violet { fill: var(--primer-violet); }`)。
- tint 平涂:同一个 hex 加 `fill-opacity=".12"` ~ `".18"`。**tint 靠 opacity 得到,不新增 token** ——
  黄色尤其如此(单档铁律,`dos-and-donts.md` §2)。
- 现成的两个 tint 底色可以直接用:`--primer-violet-soft` `#efe9fc`、`--primer-go-soft` `#e9f5ee`。
- **不用渐变。** 这套语言里没有渐变。渐变属于 atelier / glass。

三层结构,一张图齐了就成立:

1. **轮廓** 3.4 墨线,`fill="none"`。
2. **平涂** 一到两块实色或 tint,其中一块是紫的主体。
3. **细节** `class="primer-hair"` 的 1.8 线:齿、缝、刻度、书页、螺纹。
   ——第 3 层是"厚描边"和"简笔画"的分界。少了它,图是干净的,但也是空的。

## §5 手绘抖动

绘本感来自"这是手画的",不是"这是生成的"。做法是**路径偏移 ≤1.5 用户单位**:

- 一条本该水平的线,两端 y 差 1 个单位(`M20 60 L160 61`)。
- 一个本该正圆的圈,用四段三次贝塞尔,把控制点各推 1–1.5 个单位。
- 一个本该矩形的柜子,四角圆角半径写成 6 / 7 / 6.5 / 7.5。

三条纪律:

1. **≤1.5 单位。** 再大就不是手绘感,是画错了。
2. **不抖对齐关系。** 两个应该对齐的东西(标签和它指的位置、两个并排的框)必须真对齐 ——
   抖的是线,不是结构。
3. **文字不抖。** `<text>` 永远正着放,永远水平。歪着的标签是难读,不是可爱。

CSS 里 `.primer-step-num` 的圆圈已经是这个做法的现成例子:
`border-radius: 52% 48% 51% 49% / 49% 52% 48% 51%` —— 一个不太圆的圆。

## §6 SVG 里的文字

| 规矩 | 值 | 谁在查 |
|---|---|---|
| 源字号 | **≥13px** | 房规。primer 的图字比别家大,因为读者在认字不在扫图 |
| 渲染字号 | **≥10px** | visual-audit:<9px 直接告警;9.96px 是 canonical 库守住的地板 |
| `<text>` 的位置 | SVG 里**最后**画 | 半透明填充画在文字之后会盖住它,`svg-text-overlap` 会抓 |
| `aria-label` | 每个 `<svg role="img">` 必须有,写**结论**不写形状 | 跨 skill 规则 §E |

渲染字号用 §3 的同一个比例换算:`渲染字号 = 源字号 × 渲染宽度 / viewBox 宽度`。
900 viewBox 的全宽图,13px 源字号渲染到 14.6px,宽裕;190 viewBox 的比喻卡图,
13px 渲染到 11.8px,也够 —— 但:

> **比喻卡的插画最好一个字都不写。** 它的说明文字本来就在 `.primer-analogy-body` 里,
> 而且它的图宽 172px 低于机械检查的 300px 门限,机器根本不看它 —— 这一格全靠自觉。

`aria-label` 写结论的例子:

- ✅ `aria-label="书末的索引页:先在索引里查到页码，再直接翻到那一页"`
- ❌ `aria-label="一本打开的书和一个放大镜"`

## §7 标签预算

**primer 的标签预算是别家的一半。** 一张图只教一件事,标签是那件事的注解,不是图例。

| 图在哪 | `<text>` 上限 |
|---|---|
| 比喻卡 | **0**(见 §6) |
| `.primer-container` 1080 档 | **≤14** |
| `--wide` 1280 档 | **≤18** |

想放 20 个标签就是**两屏的内容**,拆成两节 —— 每节一张图,各带自己的问题。
把字号压小来塞进去,正是 `dense-diagram-labels-small` 这条检查存在的理由。

## §8 内容要铺满 viewBox

visual-audit 量所有内容元素的并集矩形:宽度方向填充 **<72%** 或高度方向 **<50%** 就告警
(`svg-letterbox`,known-bugs 1.28)。

原因和 §3 是同一个:死边距是白付的钱 —— 图被容器限宽,边距占掉的部分让**每一根线和每一个字
都按比例变细变小**。修法是把 viewBox 收紧到贴合内容(边距 ≤24 单位),不是把内容摊大。

`figure svg` 且渲染宽 ≥300px 才进这条检查,所以比喻卡的图(`<div>` 裹的,172px 宽)不进 ——
但它更该铺满:172px 的栏里,一圈空边距比什么都贵。

刻意居中的单点插画有逃生口:`data-allow-letterbox`。**用之前先确认它真的是单点插画**,
不是没收紧 viewBox。

## §9 颜色分配顺序

一张图里按这个顺序用色,用到够了就停:

1. **墨线** `#243244` —— 所有轮廓。
2. **紫** `#7a5cd6` —— 这一节的主体,一张图一处。这是招牌色,第一屏就得看见。
3. **紫 tint** `fill-opacity .12–.18` —— 主体的内部区域、背景面板。
4. **黄** `#ffd23f` —— 只圈"注意这里"的那一处,一张图最多一处。黄是马克笔,不是填充色。
5. **绿** `#3aa66b` —— 只在"完成 / 正确 / 已经懂了"的语义上。绿不承载文字(纸上 2.94:1)。
6. **纸白 / 卡白** —— 需要盖住底下线条的地方。

⚠ 第 4、5 两个色**同一张图里不要一起出现**。黄 + 绿 + 紫 同屏三次以上,页面就从"读本"
变成"信息图"(`dos-and-donts.md` §7 第 7 条)。

⚠ 不要用 `currentColor` 取色。primer 单主题,不会翻色,但 `currentColor` 会把图的颜色
绑到它所在容器的文字色上 —— 换个位置就变色,而且换的时候没人会想到图。

## §10 画完自查

1. 算过 §3 了吗?这张图在 **1024** 视口下的渲染描边 ≥3px?
2. 每个空心形状都写了 `fill="none"`?
3. 三层都在(轮廓 / 平涂 / `primer-hair` 细节)?
4. 主体是紫的,而且一张图只有一个主体?
5. `<text>` 都 ≥13px、都在 SVG 最后、都水平?数量在 §7 的预算里?
6. 内容铺满 viewBox(宽 ≥72%、高 ≥50%)?
7. `<svg role="img">` 有 `aria-label`,而且写的是结论?
8. 画的是真东西 —— 不是火柴人、不是扁平图标 + 对钩?
9. 手机截图看过了?全宽图在 375 视口下线还够粗?
