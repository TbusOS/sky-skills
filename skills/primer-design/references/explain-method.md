# primer · 拆解方法

这是 primer 的"材质文件"。其余 8 套设计 skill 做的是**给定内容 → 按美学渲染**;
primer 多一步:**先把主题拆成零基础能懂的结构,再渲染**。这份文件就是那一步的规则。

六条都是硬规则,critic 按它们打分。每条都配了一个违例和它的改写 —— 违例不是编的,
是"知道主题的人写给不知道的人"时最常出现的那种句子。

## 先做的事:写 HTML 之前先填这张表

一页 primer 通常是 3–5 个概念。每个概念填一行,填不出来的格子就是这一节还没想清:

| 概念 | 是什么(一句) | 像什么(比喻) | 关键术语 → 人话 | 数字 + 参照物 | 为什么重要 |
|---|---|---|---|---|---|
| 索引 | 一份排好序的副本 | 书末的索引页 | `全表扫描` → 一行一行看完整张表 | 2000 万行 ≈ 一行一秒要读七个多月 | 同一个查询从 4 秒到 4 毫秒 |

表填满了再开 HTML。表里的每一列都对应页面上一个真实的位置:比喻列 → `.primer-analogy`,
术语列 → `.primer-term`,数字列 → 正文或 figcaption,"为什么重要"列 → `.primer-recap` 的一点。

**表填不满的概念不要写进页面。** 少讲一个概念的页面仍然是好读本;讲了但读者没懂的那一节,
会让他怀疑前面几节是不是也没懂。

## §1 术语先翻译后使用

**规则**:没有用人话定义过的术语,不许出现在正文里。定义挂在术语**第一次**出现的地方,
用 `.primer-term`(mono 排术语,正文字排人话)。

**判据**:通读一遍正文,每个专有名词往上找 —— 页面上更早的位置必须有它的 `.primer-term`。
找不到就是违例。缩写(TLS / DNS / B-tree)同样算术语。

❌ 违例

> 查询走覆盖索引就不用回表,所以更快。

三个术语(覆盖索引 / 回表 / 走)一起出现,而且都没定义。对懂的人这句话很紧凑,
对不懂的人它是三个空格。

✅ 改写

```html
<div class="primer-term">
  <span class="primer-term-jargon">回表</span>
  <span class="primer-term-plain">在索引里找到位置以后，还得回原表把那一行取出来</span>
</div>
<p class="lang-zh">如果索引里已经有你要的那几列，数据库就不用回原表再取一次。</p>
```

术语气泡在前,正文在后。正文里再出现"回表"就是合法的了 —— 读者刚认识它。

**别把气泡当术语表堆在页尾。** 页尾的术语表读者不会往回翻;气泡的全部价值在于它就在
那个词旁边。

## §2 抽象必配比喻

**规则**:每个抽象概念必须有一个日常生活比喻,写成 `.primer-analogy` 卡,卡里自带插画。
一页至少一张(SKILL.md §6)。

**判据**:一节的主体如果是"一个你摸不到的东西"(索引、协议、缓存、密钥、队列),
这一节就必须有比喻卡。有实物的东西(硬盘、网线、按键)可以不要。

❌ 违例

> 哈希表是一种通过键计算出存储位置的数据结构,查找的平均时间复杂度是 O(1)。

这是词典释义。它对已经懂的人是准确的,对不懂的人是第二个需要被解释的句子。

✅ 改写

```html
<div class="primer-analogy">
  <div class="primer-analogy-fig"><svg viewBox="0 0 180 150" role="img"
    aria-label="衣帽间的号牌：一张号牌直接对应一个挂钩"><!-- … --></svg></div>
  <div class="primer-analogy-body">
    <p class="primer-analogy-lead lang-zh">就像……</p>
    <p class="lang-zh">寄存衣服时给你一张号牌。取的时候不用一件件翻，
      号牌上的数字就是挂钩的位置。</p>
  </div>
</div>
```

比喻的三条要求:

1. **日常的**。读者不用先懂比喻。"就像 CDN 的边缘节点"不是比喻,是又一个术语。
2. **一对一的**。号牌 ↔ 键,挂钩 ↔ 存储位置。对不上的部分别硬拉。
3. **诚实的**。比喻会在某处失效(号牌不会撞号,哈希会)。如果那个失效点是这一页要讲的东西,
   就在下一节讲它;如果不是,别提 —— 但**也别在比喻里暗示相反的事**。

## §3 数字给实物参照

**规则**:裸数字不许单独出现。每个数字跟一个参照物 —— 一个实物,或者身边一个已知的量。

**判据**:搜页面上所有数字(含单位)。每个数字所在的句子里必须有"约 / 大约 / 相当于 /
比…… / ≈"这类比照,或者一个读者已经知道的东西。

| ❌ 裸数字 | ✅ 带参照物 |
|---|---|
| 一次请求传 2MB | 一次请求传 2MB,大约一首 MP3 的大小 |
| 这张表有 2000 万行 | 这张表有 2000 万行 —— 一行一秒地读,要读七个多月 |
| 索引占 300MB | 索引占 300MB,大约是这张表本身的十分之一 |
| 查询从 4s 降到 4ms | 查询从 4 秒降到 4 毫秒,快了一千倍 |

参照物有两种,都合法:

- **实物**:一首歌、一张照片、一本书的厚度、一次眨眼。
- **比例**:"是它自己的十分之一"、"快一千倍"、"占整张表的 3%"。

⚠ 参照物必须**算得对**。2000 万秒 ÷ 86400 = 231 天,写"七个多月"是对的,写"半年"就错了。
一个算错的参照物比裸数字更糟:它会让读者不再相信这页的其它数字。

## §4 句长上限

**规则**:中文单句 **≤ 28 字**;英文单句 **≤ 18 词**。一节的正文总量 ≤ 2 句。

**判据**:数字数。中文按句末标点(`。` / `!` / `?`)断句,数汉字不数标点;英文按空格数词。
句中的逗号**不**断句 —— 28 字这个上限就是为复句设的。超了就断句,不是压缩。

❌ 违例(中文,一句 56 字)

> 由于索引本质上是一份按顺序排好的副本,数据库在查询时可以借助它跳过绝大多数不相关的行,从而把一次全表扫描变成几次定位。

✅ 改写(两句,11 字 + 26 字)

> 索引是一份排好序的副本。数据库照着它跳过不相关的行,一次全表扫描就变成几次定位。

❌ 违例(英文,一句 31 词)

> Because an index is essentially a pre-sorted copy of the column you search on, the database can use it to skip almost every irrelevant row instead of reading the whole table.

✅ 改写(两句,9 词 + 9 词)

> An index is a pre-sorted copy of one column. The database reads that copy and skips the rest.

**两种语言分别数。** 中文合规不代表英文合规 —— 而且两边长度差一倍时,双语切换会让版式跳变
(`dos-and-donts.md` §5)。写完切一次语言看版式。

## §5 讲解顺序锁定

**规则**:**是什么 → 像什么 → 怎么运作 → 为什么重要**。不许倒着来,不许跳过"像什么"。

**判据**:按 section 顺序读一遍小标题,四个阶段必须按这个次序出现。

❌ 违例的两种形状

1. **从"为什么重要"开场**:"没有索引的数据库无法支撑现代应用" —— 这是营销落地页的开场,
   它假设读者已经知道索引是什么。primer 的读者不知道。
2. **跳过"像什么"**:是什么 → 直接怎么运作。定义 + 步骤图是**文档**的结构,不是读本的。
   零基础读者在这里会认下定义但记不住它,因为没有可以挂靠的东西。

✅ 改写(以 canonical `concept` 的主题"什么是数据库索引"为例)

| 阶段 | 页面上的位置 | 内容 |
|---|---|---|
| 是什么 | hero + 第 1 节 | 索引是一份排好序的副本 |
| 像什么 | 第 1 节的 `.primer-analogy` | 就像书末的索引页:先翻索引,再翻到那一页 |
| 怎么运作 | 第 2–3 节,`.primer-step-num` 编号 | ① 建副本 ② 二分定位 ③ 取原行 |
| 为什么重要 | 第 4 节 + `.primer-recap` | 同一个查询从 4 秒到 4 毫秒;代价是写入变慢一点 |

**回顾条只收三点:是什么 / 怎么运作 / 为什么重要。** 比喻不进回顾条 —— 比喻是脚手架,
读者懂了以后就该拆掉。回顾条里出现"就像书末的索引页"说明这页没敢让概念自己站着。

`process` 页型(一步步发生了什么)的"像什么"仍然要有,只是它常常只需要一张卡:
先给整条路线一个比喻(寄信 / 点餐),再进步骤。**跳过它就成了流程文档。**

## §6 一屏一概念

**规则**:一个 `.primer-section` 只讲一件事。这既是排版规则(`dos-and-donts.md` §1)
也是内容规则。

**判据**:给每节写一个"这一节回答的问题"。写不出一个问句,或者写出了两个,就该拆。

❌ 违例

> **索引怎么工作**
> 索引是一份排好序的副本,数据库靠它二分定位。但索引不是免费的:每次写入都要同时更新索引,
> 所以写多读少的表加索引反而更慢。

一节里两个问题:"它怎么工作"和"它什么时候反而更慢"。第二个问题是真问题,值得一整节 ——
塞在这里,它既没有自己的图,也会把第一个问题的结论冲淡。

✅ 改写

- 第 3 节 —— **索引怎么找到那一行**:一张二分定位的图 + 两句。
- 第 4 节 —— **索引什么时候反而拖慢**:一张"写入要更新两处"的图 + 两句。

拆开以后每节都有自己的插画,而插画正是读者记住这一节的东西。

**一节 = 一个问题 = 一张图 + ≤2 句 +(若抽象)一张比喻卡。** 这个等式是 primer 全部
排版规则的来源。
