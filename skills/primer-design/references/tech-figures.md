# primer · 技术图画法

位域、时序、总线、数据通路、调用路径、算法 —— 这六类图和 primer 原有的科普插画差在一件事上:
**它们要同时对得起小白和工程师。**

一张位序画反的寄存器图、一张采样沿和协议相反的时序图,比没有图更糟:它教了一句假话,
而读者会拿着这句假话去读真的 datasheet。

画法的规矩仍然是 `illustration-craft.md`(线宽、viewBox 换算、`fill="none"`、SVG 文字 ≥13px)
和 `dos-and-donts.md`(黄单档、比喻卡必有、不幼稚化);这份文件只加一层:
**技术上不许说错的那些格子在哪。**

## §0 总规则:简化随便,说错不行

> 该省的都可以省。**但不许在图上放一句工程师必须来纠正的话。**

技术图解的全部难处是这条规则的两半互相拉扯。下面五种是最常犯的,每一种都不是"画得糙",
是**在教假话**:

| 画错了什么 | 读者学到的假话 |
|---|---|
| **位序反了** —— bit 0 画在左端,却按"最高位在左"标注 | 他照这张图去读 datasheet,每个字段都落在镜像位置 |
| **采样沿和协议相反** —— 写着 SPI mode 0,黄点画在下降沿 | 他按图接线,采到的是上一位 |
| **总线画成点对点** —— CPU 各拉一根线到每个外设 | "为什么不能人人直连"那一节的结论正好反了过来 |
| **握手只画一个箭头** —— valid 有箭头,ready 没有 | 他以为一方发就成交,而 valid/ready 的全部意义是两边都同意 |
| **跨带箭头跳层** —— 用户态直接连到寄存器 | 这页要纠正的正是这个误解,图替他确认了一遍 |

五条的共同点:**四道机械检查一条都不会报。** verify.py 数 class,visual-audit 量像素和字号,
axe 查对比度 —— 没有一道知道 mode 0 在哪个沿采样。这一格只有这份文件和 §9 的自查。

### 可以省的 / 不许歪的

| 放心省 | 一歪就是假话 |
|---|---|
| 流水线、预取、缓存一致性 | **位序与位宽** |
| 总线仲裁的细节、突发传输长度 | **哪个沿采样、谁在驱动这根线** |
| 时钟偏斜、抖动、上升时间的具体数 | **信号方向**(谁指向谁) |
| 错误路径、中断、超时 | **谁和谁真的连在一起** |
| 电平转换、上拉电阻的阻值 | **层与层的先后次序** |
| 多余的信号线(只画这一节要用的) | **数量级**(位宽、时钟数、砍几次) |

两条配套的纪律:

- **省掉的东西在 figcaption 里说一句。** "这里只画了片选和时钟两根线" 比画一根不存在的线好。
  一句话的成本远低于读者第二天在真手册上撞见第三根线时的困惑。
- **别拿真型号盖章。** 图和某颗真芯片的实际布局不一致时,不要在图上写它的型号和寄存器名。
  要么照真的画,要么用明显通用的名字(`DIR` / "方向寄存器")。一张看着像手册截图、内容却是编的图,
  是这六类图最坏的结局 —— 它会被人当事实引用。

## §1 位域图(bitfield)

一排格子,每格一位。这是硬件主题最常出现的一张图,也是最容易画反的一张。

### 必须画

- **位号方向标出来,而且两端都标。** 寄存器表的通行习惯是 **MSB 左 / LSB 右**:左端写 `31`,
  右端写 `0`。只标一端等于没标 —— 读者无法判断中间的字段是从哪头数的。
- **字段宽度和真实位宽成比例。** 格距固定,字段宽度 = 位数 × 格距。16 位的保留段必须是
  8 位字段的两倍宽。
- **正在讲的那个字段用 `--primer-violet` 平涂**,其余字段留白或纸白底。一张图一个主体
  (`illustration-craft.md` §9),所以一张位域图只讲一个字段。
- **保留位用 hair 斜线**(1.8 线,45°,间距 10 单位)+ 一处"保留 / Reserved"标签,不是每位一个标签。
- **位号字号 ≥13px**(源尺寸),和图内其它标签一样受 `illustration-craft.md` §6 管。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| 32 位标 32 个位号 | 不是错,是装不下 —— 双语页的标签预算见 §7 第 2 条。压小字号来塞满,正是 `dense-diagram-labels-small` 这条检查存在的理由 |
| 字段等宽排列(4 个格子代表 16/8/4/4 位) | 读者数格子会得出错的位宽,而位宽决定这个字段能装多大的数 |
| 保留位画成和可用字段一样的实色块 | 读者会以为它是个能用的字段。保留位的规矩是"读回来是什么就写回什么"(有的手册要求写 0,按手册来),它必须一眼就和可用字段不一样 |
| 格线抖动(手绘感) | 格线的位置**就是**位的位置。抖一格线 = 位错位。抖动只许留给寄存器的外框(§7 第 1 条) |
| 同一页混用两套位号习惯 | 报文图(RFC 风格)是另一套:位从 0 起、从左往右数。画报文就按报文的习惯,但**一页只许一套**,而且要在 caption 里点明是哪套 |

### 违例 → 改写

❌ 位号从左往右 0、1、2 … 31,caption 却写"最高位在左":

```svg
<text x="42"  y="52" font-size="13" fill="#243244">0</text>
<text x="906" y="52" font-size="13" fill="#243244">31</text>
```

图和字说了两件事。读者要么信图要么信字,两条路都通向错的位置。

✅ 位号方向和习惯一致,两端都标,中间只标字段边界:

```svg
<!-- MSB 左 / LSB 右;只标两端与字段边界,不标 32 个 -->
<text x="42"  y="52" font-size="13" fill="#243244">31</text>
<text x="500" y="52" font-size="13" fill="#243244">8</text>
<text x="546" y="52" font-size="13" fill="#243244">7</text>
<text x="906" y="52" font-size="13" fill="#243244">0</text>
```

每 8 位可以给一条 hair 竖线当刻度,**不给数字** —— 刻度让人数得清,数字会把预算吃光。

### viewBox

**32 位** → `viewBox="0 0 960 300"`,挂在 `.primer-container primer-container--wide` 上。

- 上限验算:1024 视口下 wide 档渲染 960px,`illustration-craft.md` §3 的上限是 960 × 1.13 = 1084;960 在限内。
- 渲染描边:1440 下 3.4 × 1280 / 960 = **4.53px**;1024 下 3.4 × 960 / 960 = **3.40px**。都过 3px 下限。
- 格距:(960 − 24 × 2) / 32 = 912 / 32 = **28.5 单位**,1440 下渲染 38.0px,1024 下 28.5px。
  13px 的两位数字宽约 14.3 单位(0.55em × 2),两侧各留 7 单位,装得下。
- 高度:300 单位 → 1440 下渲染 300 × 1280 / 960 = **400px**,离 640px 的
  `diagram-oversized` 门限还远(wide 档的高度上限是 640 / 1.333 = 480 单位)。
- 铺满(§8 那条):格排占 912 / 960 = 95% 宽;纵向内容要跨 ≥150 单位(50%),
  所以位号行 40、格排 60–130、字段括注 150–210、结论标签 260 —— 跨 220 单位 = 73%。

**8 位 / 16 位** → `viewBox="0 0 900 280"`,`.primer-container` 就够。
格距 (900 − 48) / 8 = **106.5 单位**(16 位时 53.25);描边 1440 下 4.08px / 1024 下 3.63px;
渲染高 280 × 1.2 = 336px。

## §2 时序波形(timing)

两根线上的先后次序。这张图的每一个横坐标都是一句工程断言。

### 必须画

- **时钟是方波,边沿竖直。** 一个周期 = 一段低 + 一段高,转换段 `dx = 0`(圆头描边已经给了
  1.7 单位的圆角)。要画斜边就控制在半周期的 8% 以内。
- **采样沿标出来,而且和协议一致。** 黄点(`#ffd23f`,r ≈ 7 单位)画在真正采样的那个沿上,
  一张图里黄只此一处(`illustration-craft.md` §9)。
- **数据线的有效窗口画成一段平台**,两端各一小段交叉("要变了 / 变完了"),平台正中才是可以采的部分。
- **建立/保持用一对双箭头 + 标注**:建立时间在采样沿**左边**(数据先稳住),
  保持时间在采样沿**右边**(采完才许变)。跨度 ≥24 单位,不然两个箭头头会叠在一起。
- **多信号纵向对齐靠一条 hair 竖线贯穿全部信号行。** 同一时刻在所有行上是同一个 x,
  这是"时序"这个词的全部含义。
- **片选/使能的边沿也要画。** 它什么时候拉低、什么时候放开,决定了这一帧从哪开始到哪结束。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| 采样沿和声明的模式相反 | SPI mode 0 = CPOL 0(空闲时钟低)+ CPHA 0(每周期**第一个**沿采样),第一个沿就是上升沿。把黄点画在下降沿,读者按图接线会采到上一位 |
| 数据正好在采样沿上跳变 | 采样沿附近是禁止跳变的窗口,画成同时跳变等于告诉读者建立/保持时间不存在 |
| 明显的斜坡边沿(梯形时钟) | 时序图里的明显斜坡表示"这根信号的沿很慢"(模拟量 / 上电斜坡),不是时钟 |
| 时钟边沿抖动(手绘感) | 那就是时钟抖动 —— 一个真实存在、而且是要避免的现象。边沿、采样点一律不抖(§7 第 1 条) |
| 信号行各自为政、没有贯穿的时间线 | 读者拿不到"这两件事同时发生"这个结论,而这是时序图唯一要给的东西 |
| 建立时间画在采样沿右边 | 顺序反了。反了的时序图会让人把"提前准备好"理解成"采完再准备" |

### 违例 → 改写

❌ 标题写"SPI mode 0",MOSI 在上升沿跳变,黄点也落在上升沿:

> 数据和采样同时发生 —— 这在真硬件上是竞态。读者若照此写驱动,读回来的每一位都错一拍。

✅ mode 0 的真实次序,画成三句可以逐句核对的话:

> ① 空闲时钟为低,片选先拉低。② MOSI 在**下降沿**换成下一位,在上升沿之前稳住。
> ③ 黄点画在**上升沿** —— 采的是已经稳住的那一位。

figcaption 把这三句压成一句:"片选拉低后 8 个时钟,每个上升沿采一位,数据在下降沿换。"

### viewBox

`viewBox="0 0 960 400"`,挂 `.primer-container primer-container--wide`(时钟数一多就需要横向空间)。

- 描边:1440 下 4.53px,1024 下 3.40px(同 §1 的 960 档)。
- 横向排布:信号名栏 x 24–140;波形区 x 152–936 共 **784 单位** =
  片选先拉低的空拍 48 + 8 个周期 × 88 + 收尾 32。周期 88 单位,1440 下渲染 117px,1024 下 88px;
  半周期 44 单位,斜边上限 44 × 8% = 3.5 单位。
- 纵向排布:4 条信号行(片选 / 时钟 / MOSI / MISO),行距 76 单位,y 60–364;
  顶部 40 留刻度,底部到 382 留建立/保持标注。内容跨 342 / 400 = 86%,过铺满检查。
- 高度:400 → 1440 下渲染 400 × 1.333 = **533px**,在 640px 门限内(wide 档上限 480 单位)。
- 标签清单(元素数,见 §7 第 2 条):4 个信号名(中性,各 1)+ 首末两位的位序号(中性,2)
  + 采样点 1 组双语(2)+ 建立/保持 2 组双语(4)= **12 个 `<text>`**,在 wide 档 18 的预算内。
  想给 8 位每位都写值就是 8 个额外元素 —— 只标首末两位。

## §3 总线 / SoC 框图

"芯片里面有什么"。这张图存在的唯一理由是纠正"外设各有一根私线接到 CPU"这个默认想象,
所以总线本身必须是画面上最不像一根线的东西。

### 必须画

- **主从分区。** 主设备(CPU、DMA)在上排,从设备(内存、UART、SPI)在下排,总线在中间。
  上下一分,"谁发起传输"就不用再写字解释。
- **总线画成一条街,不是一条细线。** 带高 **≥28 单位**(= 8 × 3.4 主线宽),内部平涂或 tint。
  每个设备从街上接一条**短支线**,而不是一根直达对面的长线。
- **两个方向分开画。** 地址与写数据向下,读数据向上,两条独立箭头,别合成一个双箭头。
- **地址空间画成门牌号段**:递增、不重叠,每段贴一个起始地址。
- **时钟域 / 电源域用极浅底色的背景区**(`--primer-violet-soft #efe9fc`,或调色板色 + `fill-opacity .12`),
  域边界用 hair 虚线沿区域边缘画出来,区域贴一个域名标签。
- **跨域的每个点都要显式。** 有箭头穿过域边界时,边界上画一个小方块标"同步";
  不想画同步块,就把边界画在没有箭头穿过的位置。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| CPU 各拉一根线到每个外设 | 这是点对点,不是总线。读者会得出"人人直连也行"的结论,而这一节就是要说明它为什么不行 |
| 同一段总线上同时画两笔传输 | 共享总线一次只成交一笔。画两笔等于说不需要仲裁 |
| 把 DMA 画在外设那一排 | DMA 是**主设备**,它自己发起传输。画在下排等于抹掉了"外设也能自己搬数据"这件事 —— 而这正是 DMA 存在的理由 |
| 从一个从设备画一条主动箭头去另一个从设备 | 从设备不发起传输。真会主动的那个东西,按定义就该画在上排 |
| 地址段重叠或倒序 | 地址空间是门牌号:重叠的号段在真硬件上是配置错误,不是简化 |
| 一根线直接跨过时钟域边界 | 真硬件上那正是要打同步器的地方。画成直连等于说跨域可以随便连 |
| 从"睡着"的电源域里画出一条实线箭头 | 图在说"关了电还在发信号"。域睡着时,跨出它的箭头要断在边界上 |
| 给域区上第二个色相(黄或绿) | `illustration-craft.md` §9 一张图只留一个辅助色。域是背景,不该抢主体的紫 |

### 违例 → 改写

❌ CPU 居中,四根等长的线呈放射状连到四个外设:

> 画面读起来是"CPU 有四个口"。下一节讲"为什么不能人人直连"时,读者已经从图上学会了直连。

✅ 一条 32 单位高的街横穿画面,CPU 和 DMA 在街上方各接一条短支线,四个外设在街下方各接一条:

> 街上任何时刻只画一笔传输(一个紫色的小包裹压在街面上)。
> "四个外设共用一条街"这个结论从画面本身出来,不靠文字。

### viewBox

`viewBox="0 0 900 470"`,`.primer-container` 就够(块名多是中性标签,预算不紧)。

- 描边:1440 下 3.4 × 1080 / 900 = **4.08px**,1024 下 3.4 × 960 / 900 = **3.63px**。
- 高度:470 → 1440 下渲染 470 × 1.2 = **564px**,在 640px 门限内
  (1080 档的高度上限是 640 / 1.2 = 533 单位,工作值取 ≤500)。
- 纵向排布:主设备行 y 60–170(高 110)· 总线街 y 210–242(高 **32 单位**,渲染 38.4px)·
  从设备行 y 285–395 · 域区背景 y 255–425。内容跨 60→425 = 365 / 470 = 78%,过铺满检查。
- 街高的下限从主线宽反推:3.4 × 8 = 27.2 → 取 28。低于这个,街和一根粗线在缩略图上分不出来。

## §4 IP core 内部图(数据通路与控制通路)

一块能接上总线的积木,内部分两层:货走哪里、令从哪来。这两层在画面上必须一眼分开。

### 必须画

- **一个外壳**,三组接口穿过外壳边框:寄存器接口(面向总线)· 数据口 · 时钟与复位。
  时钟与复位常被省掉,但它们是这块积木能不能接上去的前提,画一次比解释一句便宜。
- **数据通路是粗的一层**:一条平涂的带(宽 ≥20 单位)或 3.4 主线,从输入口穿过处理块到输出口,
  **一条主线走通**,不断开。
- **控制通路是细虚线的一层**:`class="primer-hair"`(1.8)+ `stroke-dasharray="2 9"`,
  从寄存器块或控制块指向数据通路上每一个被控的点。
- **寄存器块是外界唯一的入口**:CPU 一侧只有一条箭头,落在寄存器块上,不落在数据通路上。
- **握手是一对反向箭头 + 状态标注**:valid 从源指向宿,ready 从宿指向源,
  上下错开 **≥22 单位**(渲染 26px),中间一行字写清成交条件。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| valid/ready 画成一个双向箭头 | 框图里的双向箭头意思是"这根线两个方向都走数据"。valid 和 ready 是两根各走一个方向的独立线,**两个同时为高的那一拍**才成交 —— 双箭头把这层意思整个删掉了 |
| 把数据流画成穿过寄存器块 | 读者会以为吞吐量要经过 CPU 的寄存器读写。数据口和 DMA 存在的全部理由就是不走那条路 |
| 控制通路只靠颜色区分(线宽线型不变) | 印成灰度或对色不敏感的读者眼里两条线就是一条。**线宽和线型要同时变**(3.4 实线 → 1.8 虚线) |
| 画成"valid 要等 ready" | 反了。源端不许因为对方没准备好就不举 valid;宿端可以等看见 valid 再举 ready。图上画出强制次序就把这条规矩说反了 |
| 一个写着 "FSM" 的空框 | 缩写没翻译(`explain-method.md` §1)。要么画出两三个状态圈和它们之间的箭头,要么就叫它"控制板" |
| 数据通路中途断开、靠箭头暗示接续 | 断开的通路在硬件里是另一回事(跨时钟的 FIFO、寄存的一级)。想画那个就画那个,别用断线当省略号 |

### 违例 → 改写

❌ 一条双向箭头,上面写 `valid/ready`:

> 读者拿到的信息是"这里有一根双向的线"。握手真正要教的"两边都同意才交出去",一个字都没传到。

✅ 两条错开的独立箭头 + 一行成交条件:

> 上面一条从左到右:`valid` —— "我这有一件,拿去。"
> 下面一条从右到左:`ready` —— "我这有空,来吧。"
> 中间一行:两个都举手的那一拍,东西才算交出去。

### viewBox

`viewBox="0 0 900 460"`,`.primer-container`。

- 描边:4.08px(1440)/ 3.63px(1024)。
- 高度:460 → 渲染 460 × 1.2 = **552px**,在 640px 门限与 533 单位上限内。
- 排布:外壳 x 120–780 / y 60–400;数据带 y 250 一线横穿(带宽 20 单位,渲染 24px);
  寄存器块在外壳左上;控制虚线从寄存器块下引到数据带上的两个被控点;握手一对在右边框外,
  上下错开 22 单位。内容跨 60→420 = 360 / 460 = 78%,宽向 x 60→850 = 88%,过铺满检查。
- 标签清单:块名 3 个(中性)+ `valid` / `ready`(中性,2)+ 数据通路 / 控制通路 2 组双语(4)
  = **9 个 `<text>`**,在 1080 档 14 的预算内。

## §5 调用路径图

一次操作要穿过几层软件才碰到硬件。这张图靠**带**说话:带的数量就是答案。

### 必须画

- **五条等高的水平带**:用户态 / 系统调用 / 子系统 / 驱动 / 硬件。等高才让"每层花一步"读得出来。
- **每条带界一条贯通全宽的分界线**。用户态和内核态之间那条用 3.4 主线,其余四条用 hair ——
  这是全图唯一一条"要陷入内核"的边界,它值一次线宽差别。
- **带名贴左端**,每条一个双语标签。
- **去路箭头实线,每段只跨一条边界线**,箭尾在带 N 里、箭头在带 N+1 里,肉眼能看出它穿过了那条线。
- **返回路径虚线**(`stroke-dasharray="6 8"`),和去路错开,不与去路共用一条线。
- **硬件带里落到具体的东西**:一个寄存器名、一根引脚。落到一个写着"硬件"的空框等于没落。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| 跨带箭头两端都在同一条带里,靠位置暗示跨层 | 读者数不出层数,而"要穿几层"是这张图的全部内容 |
| 跳层(用户态直接连到寄存器) | 用户程序不能直接写寄存器 —— 这页要纠正的正是这个误解,图替他确认了一遍 |
| 返回箭头和去路合成一条双箭头 | 返回值和数据不是同一件事,而且返回发生在后一个时刻。双箭头把时间抹平了 |
| 返回箭头的起点和页面说法不一致 | 缓冲的 tty 在驱动把字节排进队列时就返回了,字节还没出引脚;直接写寄存器的设备才是写到硬件才返回。**两种都真实存在**,但图和字不许说两件事 —— 讲队列就从驱动带起,讲直写就从硬件带起 |
| 带高不等且没有理由 | 高的那条带会被读成"这层更重要 / 更慢",而这不是图想说的 |
| 边界线抖动 | 边界的位置就是层的位置(§7 第 1 条) |

### 违例 → 改写

❌ 一条长箭头从最上面的命令行直插到最下面的寄存器:

> 图在说"敲一行命令就写到了寄存器"。三层内核代码消失了,而这三层正是这页要讲的东西。

✅ 四段箭头,每段只跨一条边界:

> ① 命令 → `write` 进内核(穿过那条加粗的用户态/内核态边界)
> ② `write` → tty 层(子系统带里找到这台设备的驱动)
> ③ tty 层 → 驱动(驱动带)
> ④ 驱动 → 发送寄存器(硬件带,落在一个真的寄存器名上)
> 返回虚线从驱动带起,回到命令那一带 —— 因为这页讲的是"排进队列就返回"。

### viewBox

`viewBox="0 0 900 480"`,`.primer-container`。这是六类里最吃标签预算的一张。

- 描边:4.08px(1440)/ 3.63px(1024)。
- 带的算术:480 − 24 × 2 = 432 单位给 5 条带 + 4 个间隙 → 带高 76、间隙 13
  (5 × 76 + 4 × 13 = 380 + 52 = 432,正好)。带高渲染 76 × 1.2 = 91px。
- 高度:480 → 渲染 **576px**,在 640px 门限内(1080 档上限 533 单位)。
  内容跨 432 / 480 = 90%,过铺满检查。
- 标签清单:5 条带名双语 = 10 个元素 + 3 个中性步骤号 = **13 个 `<text>`**,
  1080 档预算 14 —— 只剩 1 格。
- ⚠ **想加标签就升 wide 档,但要同时改 viewBox 宽度。** 同一个 900 宽的 viewBox 放进 wide 档,
  渲染高度涨 42%:480 × 1280 / 900 = **682px**,越过 640px 门限。正确的 wide 版是
  `viewBox="0 0 960 470"` → 渲染 470 × 1280 / 960 = **627px**,标签预算 18。

## §6 算法 / 数学图

抽象量的变化。这里的诱惑是把整个过程塞进一张图,然后用箭头把它缝起来。

### 必须画

- **状态快照序列:每步一张小图,并排一行。** 读者看的是"从这张到那张变了什么",
  这个差别只有在两张图挨着时才看得见。
- **被淘汰的部分留在原位、改成 hair 空心**(1.8 描边 + `fill="none"`),不删掉。
- **每张快照下面一个剩余量的数字**,并且这些数字要真的对得上(见下面的算术)。
- **数量给实物参照**(`explain-method.md` §3),而且参照物算得对。
- **前置条件画出来。** 二分查找要求先排好序 —— 排好序这件事要么在图里看得见(卡片是递增的),
  要么单独一节讲。它不是细节,它是这个算法能成立的前提。

### 禁止

| ❌ 别画 | 它教错了什么 |
|---|---|
| 一张大图塞五步,用箭头缝起来 | 箭头会长到跨过半张图,而"每次砍一半"这个节奏在一张静态大图里读不出来 |
| 把淘汰的一半从图上删掉 | 读者看到的是"数据变少了"。真实情况是一行数据都没少,少的是**还要看的范围** |
| 用降低对比度的办法做"淘汰"效果 | 淡化的文字过不了 axe 的对比度检查(`design-tokens.md` §7)。**要淡就淡图形,不淡文字** —— 一个数字要么用 `--primer-mut`(纸上 5.97:1),要么干脆不写 |
| 剩余量的数字凑整 | 一个算错的参照物比裸数字更糟:读者会不再相信这页的其它数字(`explain-method.md` §3) |
| 省掉"必须先排好序" | 没排序时每次比较不给任何关于该去哪一半的信息 —— 算法直接不成立。这不是细节,是前提 |

### 违例 → 改写

❌ 一张图,五个箭头,中间三步的卡片被擦掉:

> 画面在说"数据被删掉了"。而二分查找一行都不删,它只是不再看另一半。

✅ 五张并排快照,淘汰的一半留在原位改成空心:

> 2000 万 → 1000 万 → 500 万 → 250 万 → 125 万,每张下面一个数。
> 五张之后再给一句结论:再这么砍 20 次就只剩一张 —— 一共 25 次。

算术要摆出来才站得住:2²⁴ = 16 777 216,不到 2000 万;2²⁵ = 33 554 432,够了。
所以 **25 次**。实物参照:一张 0.1mm 的纸对折 25 次,厚度是 0.1mm × 2²⁵ ≈ **3.4 公里** ——
比世界第一高楼叠四座还高(828m × 4 = 3312m)。翻倍这件事有多快,这句话比"指数增长"有用。

### viewBox

`viewBox="0 0 900 320"`,`.primer-container`。

- 描边:4.08px(1440)/ 3.63px(1024)。
- 五格排布:(900 − 24 × 2) / 5 = **170.4 单位**格距 → 面板宽 150 + 间隙 20.4。
  面板渲染宽 150 × 1.2 = 180px(1440)。
- 高度:320 → 渲染 **384px**。内容 y 60→282 = 222 / 320 = 69%,宽向 852 / 900 = 95%,过铺满检查。
- 标签清单:5 个剩余量数字(中性)+ "剩下" 1 组双语(2)+ "已淘汰" 1 组双语(2)
  = **9 个 `<text>`**,在 1080 档 14 的预算内。
- ⚠ 图内标签的字号仍按整张 viewBox 换算,不按小面板换算:13px 源字号在 900 / 1080 档
  渲染 15.6px,和全宽图一样宽裕。**小面板不会让字变小,别因此把字号压下去。**

## §7 六类共通的六条

技术主题不给 primer 的规矩打折。反过来,有六条在技术图上要收得更紧。

1. **承载意义的几何不抖。** `illustration-craft.md` §5 的手绘抖动只许出现在外壳和背景面板上。
   位域格线、时钟边沿、采样点、分层带边界、箭头端点 **一律不抖** ——
   抖动在这些位置上不是手绘感,它本身就是一个工程现象(时钟抖动 / 位错位)。
2. **标签预算数的是 `<text>` 元素,不是"看得见的标签"。** 双语标签是两个元素,一句话占 2。
   canonical 库最密的一张图是 12 个元素(6 组双语),1080 档的上限是 14
   (`illustration-craft.md` §7)。技术图能画得下去全靠一件事:**数字和信号名两种语言同形**
   (`31` / `SCLK` / `valid`),写一个 `<text>`、不挂 lang class,占 1 个额度。
   叙述性标签压到 2–3 组双语,剩下的额度全留给数字和信号名。
3. **一张图一个主体,主体是紫的。** 技术图里的"主体" = 正在讲的那个字段 / 那个沿 / 那个模块。
   第二处紫会让读者以为两处同等重要,而这一节只回答一个问题(`explain-method.md` §6)。
4. **黄只圈一处,且不与绿同图。** 技术图的黄归"这里就是要看的那个点":采样点、正在读的那一格。
   **别拿黄去区分字段** —— 那是把马克笔当填充色用,而且立刻违反 §9 的色序。
5. **三层结构照旧:轮廓 3.4 + 平涂 + hair 细节。** 一排空格子是表格不是插画。
   hair 层在技术图里就是刻度、斜线、栅格、引脚、螺丝孔 —— 少了它,图是干净的,也是空的。
6. **`aria-label` 写工程结论,figcaption 复述图里的每个数字。** 屏幕阅读器用户只拿到 `aria-label`
   那一句:"一张时序图"给不了任何东西,"片选拉低后 8 个时钟、每个上升沿采一位"给的是全部内容。
   figcaption 那份复述是给手机读者的 —— 375 视口下图内标签会缩到约 6px,
   数字必须在 caption 里能读到(canonical `process` 就是这么做的)。

## §8 viewBox 一览(每格都是算出来的)

`illustration-craft.md` §3 的两条公式,这份文件全部数字都从它们来:

```
渲染描边 = 3.4 × 渲染宽 / viewBox 宽        （下限 3px）
渲染高   = viewBox 高 × 渲染宽 / viewBox 宽  （上限 640px，diagram-oversized）
```

渲染宽取两个审查视口里更窄的那个算描边(1024),取更宽的那个算高度(1440)。
`.primer-container` 在 1440 下渲染 1080 / 1024 下 960;`--wide` 在 1440 下 1280 / 1024 下仍是 960。

| 图 | 容器档 | viewBox | 描边 @1440 / @1024 | 渲染高 @1440 | `<text>` |
|---|---|---|---|---|---|
| 位域(32 位) | `--wide` | `960 300` | 4.53 / 3.40 | 400px | ≤18 |
| 位域(8/16 位) | 1080 | `900 280` | 4.08 / 3.63 | 336px | ≤14 |
| 时序波形 | `--wide` | `960 400` | 4.53 / 3.40 | 533px | ≤18 |
| 总线 / SoC | 1080 | `900 470` | 4.08 / 3.63 | 564px | ≤14 |
| IP core 内部 | 1080 | `900 460` | 4.08 / 3.63 | 552px | ≤14 |
| 调用路径(5 带) | 1080 | `900 480` | 4.08 / 3.63 | 576px | ≤14 |
| 调用路径(宽版) | `--wide` | `960 470` | 4.53 / 3.40 | 627px | ≤18 |
| 算法快照(5 格) | 1080 | `900 320` | 4.08 / 3.63 | 384px | ≤14 |
| hero(技术页也一样) | hero 右栏 | `500 340` | 3.57 / 3.15 | 357px | ≤4 |
| 比喻卡 | 卡内图栏 | `180 150` | 3.25 / 3.25 | 143px | **0** |

三条从这张表读出来的规矩:

- **1080 档的 viewBox 高度上限是 533 单位**(640 / 1.2),wide 档是 **480 单位**(640 / 1.333)。
  canonical 的 `900 520` 渲染 624px,离门限只剩 16px —— 所以工作值取 ≤500。
- **换档要连 viewBox 宽度一起换。** 900 宽的图升到 wide 档,渲染高度涨 42%,
  480 单位当场变 682px 越线。宽度提到 960 才把高度按回来。
- **hero 图仍是实物,不是原理图。** 技术页的 hero 画那颗芯片、那两块板子、那根线;
  位域和波形留给节内的全宽图。hero 的 500 宽 viewBox 装不下 32 个格子,
  硬装的结果是格距 14 单位、位号 6px。

## §9 画完自查(先过工程,再过工艺)

工程五条 —— 一条不过就是在教假话,机械检查不会替你发现:

1. 位序方向和标注一致?两端都标了位号?字段宽度和位数成比例?
2. 采样沿和声明的模式一致?数据没有在采样沿上跳变?建立时间在沿的左边?
3. 总线是一条街、设备接短支线?主设备都在上排(DMA 也在)?地址段递增不重叠?
4. 握手是两条独立反向箭头 + 成交条件?控制通路的线宽**和**线型都和数据通路不同?
   CPU 一侧的箭头只落在寄存器块上?
5. 每条跨带箭头只跨一条边界、肉眼能看出穿过?没有跳层?返回路径的起点和页面的说法一致?

工艺五条 —— 转去 `illustration-craft.md` §10 走完整版,这里只列技术图特有的:

6. 承载意义的几何(格线 / 边沿 / 边界 / 采样点)一处没抖?
7. `<text>` 元素数在预算内?数字和信号名都是**中性**标签(没挂 lang class,没写两遍)?
8. 紫只有一处主体?黄只有一处、且没有和绿同图?
9. 渲染高度在 640px 以内?换了容器档以后重算过?
