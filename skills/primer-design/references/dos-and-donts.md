# primer · 品位边界

"图解读本"和"配了图的落地页"之间只隔十来条线。每条都写了**判据**,不是口号。

内容怎么拆(术语、比喻、数字、句长、讲解顺序)在 `explain-method.md`;
插画怎么画(描边、viewBox、平涂)在 `illustration-craft.md`。这份文件管的是**边界**:
什么会让页面掉出 primer,和为什么。

## §1 身份三件 —— 少一件这页就不是 primer

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| 一页没有一张比喻卡 | 比喻卡是 primer 的身份标志。其余 8 套是"给定内容 → 按美学渲染",primer 多一步内容转换,而比喻卡是那一步唯一看得见的产物。没有它,这页只是"字少一点的 sage" | 每个抽象概念配一张 `.primer-analogy`,**一页至少一张** |
| 一节里讲两三个概念 | 一屏一概念是排版规则也是内容规则。三个概念挤一屏,读者失去"我读完一件事了"的落点,而这正是零基础读者唯一的进度感 | 一个 `.primer-section` = 一件事。第二件事开新节 |
| 插画只是标题旁边的小图标 | 大图少字是这套语言的比例。图小于文,页面就退回成"带插图的文章" | 插画占该节面积 **≥ 一半** |
| 一节里三段以上正文 | 见上一条的另一半。只数**节直属正文**:这条规则的首版连比喻卡的文案一起数,而比喻卡是必备件——卡自带的 2 句把每节的正文额度当场清零,规则自相矛盾。卡的文案归卡自己的上限管(见判据) | 每节正文 **≤2 短句**(句长上限见 `explain-method.md` §4) |
| 行话没翻译就用 | 零基础读者在第一个不认识的词上就停了,后面写得再好也到不了他 | 行话第一次出现就挂 `.primer-term`;没被人话定义过的词不许进正文 |

**§1 的判据**(1440 视口截图,一节一节量;concept 页首轮评审曾把口径放宽过两处,已裁定收回):

- 每节量一次:**插画层**像素高度 ÷ 该节总高度 ≥ 0.5。插画层 = 该节 `.primer-figure` 的
  svg 与 `.primer-analogy-fig` 那一栏,**只有这两样**。圆号步骤行(`.primer-step`)和
  比喻卡整卡都**不算**插画:圆圈数字加一行 h3 主要是字,比喻卡的文案栏更是字 ——
  把它们算进"图",大图少字的比例检验就被反着用了。比喻卡的**文字**任何时候都不算进插画一侧。
- 回顾条(`.primer-recap`)所在的节**点名豁免这条比例** —— 它是 spec §3.3-6 的收尾招牌
  动作,天生是文字。豁免只此一处,不许类推到别的节。
- 每节数一次:**节正文** `<p>` 里的句子总数 ≤ 2,只数 section 直属正文。比喻卡的文案
  **不占节预算**(占了就和"比喻卡必备"自相矛盾,见上表),但受它自己的上限管:
  lead 1 句 + body ≤2 句。figcaption、`.primer-term` 的预算归 `explain-method.md`
  各自的条目管。
- 整页数一次:`.primer-analogy` ≥ 1。
- 整页搜一次:正文里的每个专有名词,页面上更早的位置有没有它的 `.primer-term`。

四个数有一个不过,不是"风格差一点",是这页没做 primer 该做的事。

⚠ 这套口径的一个几何推论:**比喻卡撑不起一个没有全宽图的节。** 卡的图栏固定 172px
(渲染高约 143px),而节的上下 padding 就有 160px,加上卡自身的边距和文案,比例上限
≈0.24。所以"像什么"永远和它的全宽插画同节 —— 拆成"比喻卡单独一节"必挂这条判据。

## §2 颜色

### 黄色单档铁律(硬)

> `--primer-marker #ffd23f` **只有一档。禁止派生深黄 token。**

实算(visual-audit 的匹配规则是逐通道 |Δ| ≤ 55 三通道同时成立):

- 马克笔黄 (255,210,63) 对 ember 金 `#c49464` (196,148,100) 是 Δ=(59,62,37) ——
  靠 r/g 两个通道**险胜**,margin 只有 4 和 7。
- 随手压深一档做 hover(230,178,60)对 ember 金 Δ=(34,30,40),**三通道全中** ——
  当场是 cross-skill smell。

所以:

| ❌ 别 | ✅ 改成 |
|---|---|
| 加 `--primer-marker-deep` / hover 用深黄 | 要更重的强调 → `--primer-violet-ink` 的紫字。primer 的重量靠紫,不靠压黄 |
| 给黄加 hover 态 | 马克笔痕不是控件,它没有状态 |
| 往浅调做黄 tint | 这个方向是安全的(离 ember 金更远),但**用 `fill-opacity` 得到,不新增 token** |

### 其余四条

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| 纯黑 `#000` / `black`(文字、描边、SVG 平涂都算) | 纸白底上的纯黑是"没调过色"的样子;primer 的墨是带蓝的 `#243244`,整页的冷暖靠它和纸白的那点温差立住 | `var(--primer-ink)`;插画描边由 CSS Section J 自动给,别自己写 `stroke="#000"` |
| 给 `--primer-ink` 加 alpha 做次级文字 | axe color-contrast 是阻断项,alpha 墨的落地值作者算不出来(`design-tokens.md` §7) | `--primer-mut` `#55617a` |
| 绿色上写文字 | `--primer-go` 在纸上只有 2.94:1 | 绿只作图形(勾、回顾条的边);绿区里的文字仍是 `--primer-ink` |
| 彩虹配色的插画 | 一张图教一件事。四个以上色相是通用信息图的味道,不是读本的 | 一张图里:墨线 + 紫(主体)+ 最多一个辅助色。分配顺序见 `illustration-craft.md` §9 |
| 偷别家的招牌色(anthropic 橙 / apple 蓝 / glass 青 / eclat flare / atelier 玫红) | 这五个在 primer 的 `forbiddenColors` 里,机器会抓 | 用 primer 自己的七个 token |

⚠ ember 金、sage 绿、lectern 蓝**刻意不进** `forbiddenColors`(原因见 `design-tokens.md` §1)。
豁免的意思是"不报警",不是"可以用" —— 真去用,critic 会抓。

## §3 厚描边不是简笔画

这是 primer 和其余 8 套最不一样的地方,也是最容易做成 slop 的地方。

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| 火柴人、笑脸圆圈、"抽象小人" | 火柴人是"我不知道画什么"的公开签名 | 画**真东西**:有齿的齿轮、有抽屉的柜子、有页脚的书、有插头的线 |
| 只有轮廓、没有平涂 | 纯线稿是图标集的语言。厚描边 + 平涂色块才是绘本的语言 | 每张图至少一块平涂(实色或 `fill-opacity` .12–.18 的 tint) |
| 只有平涂、没有细节层次 | 一块紫色 + 一条线不构成插画 | 加一层 `class="primer-hair"`(1.8px)的内部细节:齿、缝、刻度、纹理 |
| 扁平图标 + 一个对钩 | 这是 slop tell 第一名。它看着"干净",但没解释任何事 | 图要能回答这一节的那个问题;答不上就别画 |
| 描边 `stroke-width` 自己写死 | CSS Section J 已经给两个插画容器(`.primer-figure svg` 和 `.primer-analogy-fig svg`)设了线宽和圆头,自己写会和 viewBox 换算打架 | 让它继承;要整张图加粗,包一层 `<g stroke-width="4.4">` |
| 大 viewBox 装小图 | 3.4px 是**用户单位**,viewBox 越宽渲染出来越细。240 宽的 viewBox 挤在比喻卡 172px 的栏里,描边只剩 ≈2.4px —— 掉出 3px 绘本下限,当场退化成图标 | 按 `illustration-craft.md` §3 的公式定 viewBox。比喻卡插画 viewBox 宽 **≤190** |

**§3 的判据**:把页面缩到 25% 看缩略图。如果分不清这是 primer 还是任意一个 Notion 模板的
插图包,问题一定出在插画 —— 通常是"线太细"或"没有平涂"。

## §4 不幼稚化

"亲切"和"把成年人当小孩"之间的线。primer 的读者是**不懂这个主题的成年人**,不是儿童。

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| 用 emoji 当插画(🎉 / 🚀 / 💡 当图标或标题装饰) | emoji 是别人的字体在替你画画:字号、颜色、平台都不由你定,和 3.4px 描边的语言完全不搭 | 画 SVG。要一个灯泡就画一个有螺口和玻璃的灯泡 |
| 满页卡通脸 | 一个有表情的角色可以是一节的主体;每张图都有脸就成了儿童读物 | 全页最多一处拟人,而且它得是那一节真正的主体 |
| 感叹号堆叠、"超简单!"、"一看就懂!" | 承诺读者会懂,不如让他真懂。这类语气是在替读者鼓掌 | 陈述句。"索引让数据库不用一行一行找。" |
| 拿"小朋友都懂"这类话当亲切 | 读者是成年人,他只是不懂这个主题 | 讲清楚就是尊重,不用附加安慰 |
| 用糖果色 / 大量圆角贴纸 / 弹跳动效 | 绘本感来自**线和留白**,不来自装饰 | primer 全页只有语言切换钮有 180ms 过渡。读本不动 |

参照物是《How It Works》和 DK 图解百科:成年小白读完不觉得被当小孩。

## §5 语言与排版

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| zh 段落里用半角 `,;:` | verify.py 会拦。半角标点在 CJK 里字距不对 | 全角 `，；：`。zh span 内一律 |
| 中文字体栈少 `Noto Sans SC` | Fredoka 零 CJK 覆盖,漏了栈中文就落到系统默认,和拉丁字重完全对不齐(跨 skill 规则 §H) | 两个字栈都带 `Noto Sans SC`(`design-tokens.md` §3 已经带了,别改) |
| 斜体 | 这套语言里没有斜体的位置。Fredoka / Nunito 的斜体在大字号下像临时倾斜的贴纸 | 强调靠 `.primer-mark`(黄)或 `--primer-violet-ink`(紫字) |
| `.primer-mark` 圈整句 | 全高亮 = 没高亮 | 只圈一句里最要紧的那几个字 |
| 只写一种语言 | 公开站页必须双语(跨 skill 规则 §G,verify.py 强制) | 每段 `<span class="lang-en">` + `<span class="lang-zh">`,默认中文 |
| 中英译文长度差一倍 | 双语切换后版式跳变,一边的插画会浮起来 | 两种语言都守 `explain-method.md` §4 的句长上限,写完切一次看版式 |
| 互联网黑话(禁用清单见用户的 `~/.claude/rules/language.md`) | 这类词在**讲给外行的页面上**是最贵的错:被稀释到近乎无意义的抽象词,正是读者听不懂的那一类,而且它们连"可以查"的余地都不给 —— 至少一个真术语能被查到 | 白话 + 精确术语。真术语进 `.primer-term` 并翻译,白话进正文。写完 grep 一遍禁用清单 |

## §6 结构与语义

| ❌ 别 | 为什么 | ✅ 改成 |
|---|---|---|
| `.primer-figure` 里没有 `<figcaption>` | `.primer-figure` 是**真的 `<figure>` 元素**,visual-audit 对"figure 没有 figcaption"直接告警(known-bugs 1.18);SVG 的 `aria-label` 和图内 `<text>` 都不算 caption | 每个 `.primer-figure` 里 `</svg>` 之后跟一个真的 `<figcaption class="primer-figcaption">` |
| 给比喻卡里的插画套 `<figure>` | 比喻卡的说明文字本来就在 `.primer-analogy-body` 里,再加 caption 是重复;套 `<figure>` 只会触发上面那条告警 | 比喻卡的插画用 `<div class="primer-analogy-fig">` —— **刻意**不是 `<figure>`,就是为了绕开那条检查。它的线宽由 CSS Section J 一并管,不会掉队 |
| hero 用 `.primer-container--narrow` | verify.py 查 `.primer-hero` 里第一个元素,narrow 档直接报错 | `.primer-container` 或 `--wide` |
| 修饰符单独写 `class="primer-container--wide"` | 修饰符只带宽度,不带 padding 和居中 | `class="primer-container primer-container--wide"` |
| 自己给招牌组件另起 class 名 | verify.py 只校验 `primer-*` 是否定义在 CSS 里;新起的 `primer-xxx` 是未定义 class,直接报错 | 用 SKILL.md §1.5 列的那几个;页面局部样式用**无前缀** class 写在页内 `<style>` |
| 去掉 focus 轮廓 | 键盘可见性是可达性错误,不是品位选择 | CSS 已经给了 3px `--primer-violet-ink` 轮廓,别覆盖 |

## §7 最容易犯的几个错

1. **比喻卡插画的描边变细。** 症状不是报错,是"这张图看着比别的图轻"。原因永远是
   viewBox 太宽(比喻卡的图栏只有 172px)。修法见 `illustration-craft.md` §3。
2. **hollow 形状忘了 `fill="none"`。** SVG 的默认 fill 是**黑色**,不是透明。一个本该是
   空心圆的形状会渲染成一个黑饼,而且机械检查不报错。
3. **正文越写越长。** 第一节两句、第三节四句、第五节一整段 —— 这是"内容转换"半途放弃的
   典型形状。写完从最后一节往前读一遍。
4. **术语气泡放在术语第**二**次出现的地方。** 第一次出现才是有用的位置。
5. **回顾条写成摘要。** `.primer-recap` 是"现在你知道了"三点,每点对应页面上真的讲过的一件事;
   写成"本文介绍了……"就白占了一个招牌组件。
6. **插画标签越加越多。** 1080 档 ≤14 个标签。想放 20 个就拆成两屏 —— 一张图只教一件事。
7. **黄绿紫一起上。** 三个辅助色同屏出现三次以上,页面就从"读本"变成"信息图"。
   紫是招牌,黄是划线,绿只在结尾。

## §8 交付前检查

```bash
bin/design-review --skill=primer <页面>.html          # 结构 + 渲染 + 可达性 + 截图
bin/design-review --skill=primer --pixel <页面>.html  # 再加像素回归(需已有基线)
```

第三道是 **axe-core**,color-contrast 是阻断项。任一 error = 任务没完成。
机械检查是必要条件不是充分条件:**截图必须人眼看过**(SKILL.md §5)。
