## 3. 定死的五样

**判断标准**:五样都在,黑白、彩色、技术图、壁纸都还是水墨;少一样就不是了。
SKILL.md 第 1 节照下表写(R-F01)。

| 样 | 怎么做 | 没有它会怎样 |
|---|---|---|
| 1 纸 | 宣纸暖白底,带纤维纹理;深色版用磁青纸(深靛蓝)配泥金线,**另画,不反相** | 纯白底像打印稿;反相成黑底白线像底片,墨的味道全没了 |
| 2 墨和色都是水做的 | 墨分五色(焦、浓、重、淡、清),层级靠浓淡;颜色用国画颜料,透明、一层层叠、边缘湿润;**不平涂、不用一眼看得出的矢量渐变** | 平涂像扁平插画或剪纸;硬渐变像 PPT |
| 3 笔有提按 | 线有粗细变化:起笔重、行笔轻、收笔回锋;快处飞白,停处晕开 | 等宽线就成了线描或图标,跟 graphite 分不开 |
| 4 留白当画 | 水、天、雾不画,靠空着表达;字放在留白里。留多少按场景定,但留白一定是设计过的 | 画满了像西洋水彩或油画,也没地方放字 |
| 5 一方印 + 书法字 | 标题用毛笔字体(楷、行、草按场景选),正文宋体或楷体;至少一方朱印,当画面的「句号」;可竖排 | 没有印像没画完;标题用无衬线体立刻退回网页模板 |

### 3.1 纸(初值)

| 变量 | 浅色(宣纸) | 深色(磁青纸) | 用在哪 |
|---|---|---|---|
| `--ink-paper` | `#f2ead8` | `#14213a` | 页面底、插画的纸 |
| `--ink-paper-2` | `#ebe1cb` | `#1a2944` | 第二种底 |
| `--ink-card` | `#f8f3e7` | `#1d2d4a` | 卡片、图的舞台 |
| `--ink-rule` | `#d9ccb2` | `#2c3d5c` | 分隔线 |

- 纤维纹理:一张小噪点图 + 几条极淡的长纤维;单独的 SVG 里用滤镜。
- **深色版为什么是磁青纸配泥金**:这是古代写经的真实做法,深底上的金线本身就是一种成立的画法;
  反相会把墨变成白色,失去墨的质感(graphite 实测过反相的问题,见 `graphite-design/references/material.md` §1)。

### 3.2 五档墨色(初值)

| 档 | 浅色 | 深色(泥金由亮到暗) | 常用来 |
|---|---|---|---|
| 焦 | `#1a1714` | `#f0d89a` | 最要紧的一笔、点睛、标题 |
| 浓 | `#2e2a26` | `#d9b96e` | 主体轮廓、正在讲的部分 |
| 重 | `#4f4943` | `#b7995a` | 次要轮廓 |
| 淡 | `#8a837a` | `#8a7650` | 远处、背景结构、基础设施 |
| 清 | `#c3bcb0` | `#5c5240` | 最远的山、雾、底纹 |

拿来写字时只用焦、浓两档,且与纸的对比度 ≥ 4.5:1(R-N05)。

### 3.3 颜料与四种设色(初值)

| 颜料 | 浅色 | 常干的事 |
|---|---|---|
| 花青 | `#3e5f7a` | 水、远山、冷的东西、用户一侧 |
| 赭石 | `#a8643a` | 山石、秋、土、木 |
| 藤黄 | `#d9a521` | 光、判断节点、点亮 |
| 胭脂 | `#9d2933` | 花、警告 |
| 石青 | `#2f6f9f` | 青绿山水、重点(冷) |
| 石绿 | `#3f8f74` | 青绿山水、通过、存储 |
| 朱砂 | `#b8322a` | 印章、最重要的一处 |
| 朱膘 | `#d8673c` | 秋叶、正在发生的那一处 |
| 白粉 | `#f3efe6` | 雪、深色版上的高光 |

深色版的颜料值在 P2 定,规则是:在磁青纸上保持「透明叠色」的感觉,用于写字的那一档对比度 ≥ 4.5:1。

| 设色方式 | 用哪些颜料 | 适合 |
|---|---|---|
| 纯水墨 | 只有墨 + 印 | 技术图、冬景、武侠、诗词 |
| 浅绛 | 墨 + 淡赭石、淡花青 | 秋景、文档插图、界面点缀 |
| 青绿 | 墨 + 石青、石绿,颜色重 | 发布会、壁纸、夏景 |
| 彩墨 / 没骨 | 不勾墨线,颜色直接泼染 | 春景、动漫、海报 |

**颜色预算**:同一种颜色在一张图里只代表一件事;颜色种类少于要讲的事(沿用 graphite 的规矩)。

### 3.4 字

| 用途 | 字体 |
|---|---|
| 标题、画上题字 | 毛笔字体,候选:马善政楷书(Ma Shan Zheng)、志莽行书(Zhi Mang Xing)、刘建毛草(Liu Jian Mao Cao)、龙藏体(Long Cang)。**许可证 P0 逐个查证,出处写进 `material.md`,不合格的不用**(R-N04) |
| 图里的说明、批注 | 霞鹜文楷 GB 屏幕阅读版(本仓已有) |
| 正文 | Noto Serif SC(本仓已有) |
| 代码、数字 | JetBrains Mono(本仓已有,关掉连字) |

- 毛笔字体只用在标题和题字,**不当正文**:草书、行书小字号时读不出来。
- 位图里不出现任何字(R-F34)。
- 所有字体按实际用字做子集(`design-review/scripts/build_fonts.py`),`check_fonts.py` 通过(R-F72)。

### 3.5 动画规则

1. **按笔顺**:先主后次;同一组里先勾后染。
2. **一支笔**:同一时间只画一笔;一笔的时长和长度相关,重按的地方慢、轻扫的地方快。
3. **落定后晕开**:一笔显完,晕边再慢慢扩开(0.6–1.5 秒,初值)。
4. **环境慢动**:雾、水、云的动作周期 ≥ 6 秒;雨、雪、落花是例外,但也比 graphite 的雨慢。
5. **一个时钟**:画面、代码高亮、计数、字幕都从同一个时间算。
6. **关掉动画也完整**(R-F14)。

## 4. 场景四问与场景表

SKILL.md 把这一节放在画法之前(R-F04):先定要做成什么样,再动笔。

### 4.1 先问四件事

1. **在哪看**:网页、手机竖屏视频、桌面壁纸、发布会大屏、文档插图 → 定比例、最小字号、安全区。
2. **读者要得到什么**:看懂一个机制 / 感受一种气氛 / 记住一个产品 / 找到一个按钮 → 「读懂优先」还是「气氛优先」。
3. **动不动、多长** → 节奏。
4. **有没有必须准确的东西**(字、数、连线、代码)→ 有就代码画,不交给出图模型。

### 4.2 场景表(R-F05)

| 场景组 | 优先 | 留白 | 设色 | 笔法 / 字 | 动画 | 谁画 | 常见坑 |
|---|---|---|---|---|---|---|---|
| 技术图(框图、流程、算法、数学、代码讲解) | 读懂 | 2–3.5 成 | 纯墨或浅绛,一色一事 | 工整,线必须连对;楷体标签 + 等宽代码 | 按数据流 / 算法步骤画,墨点沿线走 | 代码 | 飞白把箭头断开;晕染吃掉字 |
| 页面与界面(技术文档、web、UI) | 读懂 + 好用 | 按版式 | 水墨只做点缀:书法标题、墨痕分隔线、印章当徽标或状态、空状态小画 | 正文宋体或楷体,毛笔字不当正文 | 滚动时段落随墨晕显出;按钮按下墨晕开 | 代码 | 宣纸纹理拉低文字对比度 |
| 发布会(产品介绍) | 记住产品 | 大 | 磁青纸泥金,或宣纸大留白 + 一处重彩 | 一屏一句话,巨大书法字 | 泼墨揭幕;一笔横扫写出标题 | 叠用 | 元素太多抢了产品 |
| 叙事画面(电影、动漫、短剧、武侠、太极) | 气氛 | 中到大 | 焦墨高对比,或彩墨 | 泼墨;刀光、速度线用飞白 | 镜头推拉,风、雨、落叶;剪影一笔画出 | 择优 | 出图模型乱写字;人脸崩 |
| 静赏(诗词、山水、四季、壁纸) | 气氛 | 5–7 成 | 按季节:春花青、嫩绿、胭脂;夏浓墨重绿;秋赭石、朱膘;冬留白当雪 | 诗竖排题在留白处,配一方印 | 慢:雾移、水波、落花、落雪 | 择优 | 壁纸图标区被画占 |

这 5 组同时是口味学习的场景组(§10.3)。组数少,每组攒的记录才够用。

### 4.3 技术图里的水墨比喻(给 AI 的起点,不是规定)

- **远淡近浓 = 层次**:底层基础设施画成淡墨远山,正在讲的那层用浓墨。
- **水 = 数据流**:数据像水沿渠流,分叉就是分支。
- **墨块 = 节点**,**笔触箭头 = 调用**。
- 比喻要在说明里标明是比喻。

| 画什么 | 用谁 | 为什么 |
|---|---|---|
| 技术类(框图、流程、代码、数学、数据图、界面) | 代码 | 字要对、线要连对、数要算对;出图模型会写错字、连错线(graphite 实测) |
| 艺术类(诗词、四季、山水、武侠、电影、壁纸、发布会画面) | **两边各画一版,择优** | 出图模型质感好;代码画的能逐笔动、能换主题。哪个更好要看题目,不预设 |
| 开场、比喻 | 可叠用 | 位图当底,代码画会动的部分 |

**择优流程**(R-F30–R-F32):

1. 同一题目,我用代码设计并做成会动的一版;出图模型(本机 `codex exec -m gpt-6-astra`,提示词走标准输入)出一版位图。
2. 两版放进 `compare.html` 并排。
3. 按四条选:五样都在没有;场景目标达到没有;动起来好不好看;能不能换主题和语言。
4. 选中的进图例库;落选的连同理由记进 `references/image-prompts.md`。

出图模型的提示词骨架沿用 graphite `references/image-prompts.md` 的写法(参考图定画风、颜色预算写死、
要叠东西的地方画成平整空白、图里不要字、夜间版另出)。水墨专用的参考图在 P4 第一张定稿后固定下来,
后面每张都附上,保证同一套里人物和笔墨一致。

## 6. 画笔代码与动画

### 6.1 一笔的数据

```js
B.stroke(points, {
  tone: 'nong',          // 五档墨色之一,或颜料名 'huaqing' …
  width: 14,             // 最粗处宽度(px)
  press: 'zhong',        // 提按曲线:'zhong' 中锋 | 'ce' 侧锋 | 'si' 游丝
  load: 0.9,             // 起笔时含墨量,沿笔路递减;低于阈值出飞白
  wet: 0.6               // 晕边强度
});
```

- **提按曲线**:沿笔路 0→1 的位置 t 给出宽度系数。中锋:起笔很快到 1(带一个小回钩表示藏锋),
  行笔 0.6–0.8,收笔回锋收细。
- **含墨量**:沿笔路线性递减,再叠一点随机起伏。

### 6.2 湿笔、飞白、晕边

- **湿的部分**:按宽度系数把中心线往两边偏出去,围成填色形状;边缘用噪声位移滤镜打毛。
- **飞白**:把笔头当成一束笔毛(根数 = 宽度 / 2,取 6–24),每根是一条细线;含墨量低的地方,
  笔毛断成虚线,露出纸白。
- **晕边**:同一形状再画一层,更淡、更模糊,垫在下面。
- **怎么按时显出来**:graphite 的落笔动画是改虚线样式,但飞白本身已经用了虚线样式,两者冲突
  (graphite 踩过同类坑:「虚线没有落笔动画」)。所以每一笔外套一层遮罩:遮罩是一条比笔最粗处
  还宽的线,沿笔路展开,露出下面整笔。湿笔、飞白都只靠这一种方式显出。
- **晕开**:一笔显完后,晕边层的透明度和模糊半径在 0.6–1.5 秒内增大。

**风险**:每笔一个遮罩,一张图几百笔时浏览器可能卡。P0 小样 3 实测,结论定元素数上限(R-N06)。

### 6.3 墨叠墨、大片淡墨、印章

- **墨叠墨**:浅色版墨层用正片叠底,两笔交叠处更深。深色版的泥金线用普通混合(金叠金不该变暗)。
- **大片淡墨**(远山、雾、水):几层半透明形状叠加,边缘噪声打毛,形状内用不规则的浓淡,
  不用平滑渐变。
- **印章**:方印或圆印,朱文(红字)或白文(红底留白字),边缘用噪声蚀出残缺;盖印动画是印落下、颜色压实。

### 6.4 颜色走 class

沿用 graphite 的做法:每样东西带一个 class(`.ink-jiao` `.ink-p-huaqing` …),由 `ink.css` 映射到 CSS 变量,
换主题就变色(R-F15)。SVG 属性里不写 `var()`(不生效)。

### 6.5 时间表

接口与 graphite 一致(R-F11):`at(start, dur, fn)` 一组按长度分时间;`track` / `follow` 按时刻走到几个位置;
`window(t0, t1, fn)` 只在这段时间出现(带 `tmp`,静态画面里隐藏);`id('名字')` 生成带本图前缀的 id。

**为什么不跟 graphite 共用代码**:铅笔是等宽线 + 排线,毛笔是变宽形状 + 笔毛 + 晕边,画法完全不同;
相同的只有时间表的思路。时间表这部分照 graphite 的接口重写,等第三个要逐笔动画的风格出现时再抽成共用。

### 6.6 物件(`props.js`)

- 植物:梅、兰、竹、菊、松(竹叶、兰叶各是一笔,正好练提按)。
- 山水:山石(带皴)、水波、云、雾、舟、亭、桥、远山。
- 人物和动物:剪影为主(侠客、书生、打太极的人),鹤、鱼、马。
- 图表件:墨块框、笔触箭头、判断、代码卡(宣纸底或深色底)、公式。
- 坐标用局部 (u, v) 换算,不用 SVG 的 `transform: scale`(会把笔的宽度一起缩,沿用 graphite 的规矩)。

### 6.7 字体子集

毛笔字体字库大,只按实际用字做子集。新加汉字后跑 `build_fonts.py` 和 `check_fonts.py`。

## 7. 位图怎么动起来(R-F18)

1. 出图模型按同一构图,把远山、中景、主体、前景**分别**出成单独的图,每张画在白纸上。
2. `scripts/layers.mjs` 用 playwright 在浏览器里按亮度抠层:
   透明度 a = clamp((L纸 − L) / (L纸 − L最暗)),颜色按「叠在纸上」反推回去,输出带透明的 WebP。
   本机 python 没有 PIL,所以不用 Python 处理图像(R-N07)。
3. 网页里各层视差移动,层间夹雾;开场用一个噪声打毛、逐渐扩大的遮罩,让画面像墨晕开一样显出。

**P0 小样 2 不过关**(边缘有白边、颜色发灰)时,改成「位图当底 + 代码画会动的前景(雨、雪、落花、飞鸟、晕开的墨)」,
并在本节记下结论(需求 Q3)。

## 10. `design-taste`:所有设计 skill 共用的口味学习

### 10.1 文件分工(R-F50)

```
skills/design-taste/
  SKILL.md
  assets/taste-core.js     引擎:估计、出题、解释(浏览器和命令行共用)
  assets/shared.js         共享参数(字号、颜色数、留白、节奏、主题)和共享词表
  assets/provenance.js     页面上「画上留出处」的小印和弹出说明
  scripts/taste.mjs        命令行:suggest / ab / pick / say / ref / ingest / explain / import / --self-test
  scripts/measure.mjs      看图识口味:用 playwright 读像素、量统计值
skills/<风格>-design/assets/taste-profile.js
                           这个风格的参数、默认值、范围、专属词表、看图换算、apply()
```

引擎不认识任何具体风格,只读参数表。新风格接入 = 写一个 `taste-profile.js`。

### 10.2 口味日志(R-F51)

- 位置:`~/.config/sky-skills/taste.jsonl`(`SKY_TASTE_DIR` 可改),只在本机(R-N08)。
- 每行一条事件:`{ ts, style, scene, kind, knob?, a?, b?, winner?, value?, text?, source? }`,
  `kind` 为 `pick` `keep` `drop` `say` `review` `ref`。
- 旧文件 `graphite-taste.jsonl` 照读,读进来时补 `style: 'graphite'`、`scene: null`。

### 10.3 分场景记(R-F52)

一个参数的值分两步算:

1. **风格总口味**:沿用 graphite 现有算法——从默认值出发(起点权重 2),按时间顺序逐条做加权平均;
   挑选权重 1、说的话 1、留下 / 删掉 0.5、审查意见 0.3;90 天前的记录算一半;累计权重封顶 8;
   最后套上审查器定的上下限。
2. **场景口味**:从风格总口味出发(起点权重 2),只走这个场景组的记录,算法同上。

**为什么这样分**:某个场景只有一两条记录时,结果仍然贴近总口味,不会被一次挑选带偏;
记录多了,场景口味才离开总口味。只多一个起点,解释起来仍是「默认 → 总口味 → 场景」一条链。

**退化**:查询不带场景时只算第 1 步;只有一个风格时,第 1 步与 graphite 现有算法逐步相同。
这一点由 R-F56 的「graphite 重新生成无差异」验证。

### 10.4 看图识口味(R-F53)

`taste.mjs ref --style inkwash 图1.jpg 图2.jpg`:

| 量什么 | 怎么量 | 换成哪个参数 |
|---|---|---|
| 留白占比 | 取最亮那批像素的众数当纸色;跟纸色接近且不饱和的像素占比 | 留白(共享) |
| 墨色五档分布 | 非纸像素按亮度分五档的占比 | 墨浓淡(水墨专属) |
| 色彩多少、偏哪种颜色 | 色彩丰富度 + 色相分布;占比 > 3% 的色相簇个数 | 颜色数(共享)、设色方式(水墨专属) |
| 边缘晕开程度 | 边缘处柔和过渡与硬边的像素比 | 湿度(水墨专属) |

- 每张参考图记一条 `ref` 事件,权重 0.5(相当于「留下」一张)。
- 量得出的才换算;飞白多少量不准,不换算,文档里写明。
- 换算函数由各风格的 `taste-profile.js` 提供(graphite 的排线疏密没法从一张水墨画里量)。
- 自测:用代码生成已知留白比例的测试图,量出来误差 ≤ ±0.05。

### 10.5 跨风格共享(R-F54)

- 共享参数只有 5 个:字号、颜色数、留白、节奏、主题。各风格在参数表里声明自己哪个参数对应哪个共享参数。
- 别的风格的记录,传过来的是「比那个风格的默认值偏了多少」,按范围换算:
  偏移 = (x − 那边默认) / (那边上限 − 那边下限);这边的值 = 这边默认 + 偏移 × (这边上限 − 这边下限)。
  **为什么不传绝对值**:graphite 的留白默认 0.45,水墨默认更大;直接搬值会把水墨拉得过满。
- 传过来的记录权重打五折:同一句「字太小」在别的风格里说的,不如在本风格里说的有分量。
- 说的话:词表分共享词(「字太小」「太花」「太快」)和风格专属词(「飞白太多」「太湿」);只有共享词跨风格生效。
- 风格专属参数一律不传。

### 10.6 画上留出处(R-F55)

- 网页里每张按口味画的图,角上一个小印;点开列出偏离默认值的参数和推动它的记录
  (内容就是 `explain()` 的输出,两处一致)。
- SVG 根元素写 `data-taste`,记下当时用的参数值,以后能查这张图是按什么口味画的。
- 导出的壁纸和视频默认不带;加 `--provenance` 才在角落写一行题跋小字。
  **为什么默认不带**:壁纸和视频是成品,不该有调试信息。

### 10.7 graphite 迁移(R-F56)

- `graphite-design/assets/taste.js` 变成两部分:参数表 → `taste-profile.js`;原文件保留成一个薄包装,
  加载引擎并绑定 graphite 参数表,对外接口不变(`90-taste.mjs` 和展示页的口味实验室照常用)。
- `graphite-design/scripts/taste.mjs` 转调 `design-taste/scripts/taste.mjs --style graphite`,原有命令照常可用。
- 验收:原 40 题自测通过;「越用越懂你」3 张图重新生成后 `build.mjs --check` 无差异。

### 10.8 自测

| 自测 | 通过条件 |
|---|---|
| 原 graphite 40 题模拟 | 照旧通过 |
| 分场景:读者 A 技术图爱淡、壁纸爱浓 | 两组都学到正确方向 |
| 分场景:读者 B 各组口味相同 | 两组的值差距不超过 1 个步长 |
| 跨风格:在 graphite 说「字太小」 | 水墨字号往大走 |
| 跨风格:graphite 排线参数被反复挑选 | 水墨任何参数都不动 |
| 看图:已知留白的测试图 | 误差 ≤ ±0.05 |
| 故意改坏 | 关掉场景那一步 / 关掉跨风格换算 / 关掉五折时,对应自测失败(R-N03) |

## 11. 通用方法 `design-skill-method`(私有 skill 仓)

### 11.1 内容(R-F60、R-F62)

1. 做一个设计风格 skill 的步骤(R-F60 所列),每步写清要产出什么、怎么算做完。
2. 两档标准(§11.2)。
3. 现有 11 个设计 skill 踩过的坑,每条带出处。
4. 本仓专属的注册点清单单独放一个参数文件,方法正文不写死本仓路径。

### 11.2 两档标准(R-F61)

| 档 | 要求 |
|---|---|
| 基础档(每个设计 skill 都要达到) | SKILL.md 有定死表且每行有「没有它会怎样」;有放开清单;有场景四问和场景表;有谁来画;深色版另画的说明和 CSS 深色变量;有检查命令;有 `taste-profile.js` 且能被 `design-taste` 加载;注册点全部接上 |
| 完整档(按需补) | 图例库 ≥ 30 张且分类;有会动的图例且关掉动画完整;位图有提示词记录;有导出脚本;展示页过 `check_objective`;`build.mjs --check` 通过 |

### 11.3 两个检查脚本

| 脚本 | 做什么 | 什么时候跑 |
|---|---|---|
| `check_registration.sh <skill>` | 按注册点清单逐处查有没有这个 skill,列出缺的(R-F63) | P0 先对 graphite 跑;P5 对水墨和 `design-taste` 跑 |
| `check_skill.mjs <skill>` | 按两档逐项查,每项输出通过 / 不通过和原因(R-F64) | P5 对水墨跑;下一轮对其他 10 个跑,得到改造清单 |

注册点清单的来源:graphite 那次提交(`12189d0`)实际改过的文件,加 primer 设计书 §8 的清单。
primer 设计书 §8.5 记录过上一个 skill 漏接的一串,所以先拿 graphite 跑,看脚本能不能查出漏接。

两个脚本都带 `--selftest`,去掉检查逻辑后自测必须失败(R-N03)。

## 14. 风险

| 风险 | 后果 | 怎么应对 |
|---|---|---|
| 代码画的毛笔不像 | 水墨的核心立不住 | P0 小样 1 先做一笔湿笔 + 一笔飞白 + 晕开,截图对照真毛笔照片;不像就先改画法再开工 |
| 位图抠层边缘脏 | 位图动画做不成 | P0 小样 2 验证;不行就退回「位图当底 + 代码前景」(§7) |
| 每笔一个遮罩太重 | 页面卡、导出慢 | P0 小样 3 画 200 笔实测,定元素数上限;超了就合并同组的遮罩 |
| 毛笔字体许可证不合格 | 不能放进公开仓 | P0 逐个查证;不合格的不用,标题退回霞鹜文楷 |
| 出图慢(一张 2–6 分钟,约 20 题) | 拖长 P4 | 整批放后台顺序跑,同时写代码 |
| 跨风格换算让口味跑偏 | 用户觉得「它没学对」 | 只共享 5 个参数、五折、按范围换算;自测里有「专属参数不动」一项 |
| 毛笔字子集体积大 | 页面加载慢 | 只按实际用字做子集;标题字少 |
